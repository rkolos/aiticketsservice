## Замечания по коду и окружению

### Блокирующие для тестов / среды
- Интеграционные тесты `tests/infrastructure/dify/uploadFile.integration.test.js` падают, пока в Dify не настроена модель эмбеддингов: ошибка `Default model not found for text-embedding`. Требуется выбрать Text Embedding Model в Dify Settings → Model Provider.
- В логах тестов видно `Redis connection error {"error":"NOAUTH Authentication required."}` — Redis запущен с паролем. Нужны корректные `REDIS_HOST/PORT/PASSWORD` в `.env` тестовой среды или отключить пароль для локального Redis.

### Поведение/риски в коде
- `fastLaneProcessor.js` — заглушка, не используется (воркер собирается через `fastLaneWorker`). Файл можно удалить или реализовать/убрать из репо, чтобы не вводил в заблуждение.
- В `fastLaneWorker` для `CMD_ANALYZE_NEW_TICKET` ошибки парсинга JSON (невалидный ответ LLM) приводят к отправке ошибки в resultQueue, но исходный текст не логируется (только ошибка). Для диагностики можно логировать укороченный raw-ответ (без секретов).
- В `FileService.downloadStream` idle-таймер создаётся без `unref`, из-за чего при ошибках в потоках тесты могут жаловаться на «force exit». Таймер лучше `unref()` или гарантированно очищать при всех выходах (сейчас очищается, но warning всё ещё возможен при неожиданных путях завершения).
- В `OrganizationService.ensureAdminKb/ensureHistoryKb` при большом количестве датасетов возможно множество запросов без ограничений. Если Dify медленный, стоит добавить простую защиту (limit страниц из конфига или задержку). Пока не критично, но учитывайте при большом объёме.
- В `index.js` при неуспешном cache warming процесс сразу `exit(1)`. Это правильно по ТЗ, но если Redis/Dify кратковременно недоступны при старте, сервис не поднимется. Учтите для прод-оркестратора (нужен рестарт/бэкофф).

### Инфраструктура/конфиг
- Добавлен `DIFY_LIST_DATASETS_PAGE_LIMIT` — не забудьте проставить в `.env` для стейдж/прода, если требуется иное значение страницы.
- В логах много сообщений от `dotenv` о загрузке `.env`. Если шумно, можно выключить verbose-режим (`DOTENV_CONFIG_DEBUG=false`).

### Остаточные предупреждения тестов
- Jest выводит предупреждение «A worker process has failed to exit gracefully…». Часто причина — открытые соединения Redis или таймеры в интеграционных тестах. После настройки Redis-password и Dify embedding модели перепроверьте: если предупреждение останется, нужно убедиться, что все таймеры `unref()` и все Redis-коннекты закрываются (особенно в интеграционных тестах).

### Что сделать, чтобы тесты стали зелёными
1) Настроить embedding модель в Dify (Text Embedding Model).  
2) Обновить `.env` для тестов, чтобы Redis подключался без NOAUTH (либо снять пароль).  
3) Повторно запустить `npm test`. Если останется предупреждение про graceful exit — проверить незакрытые таймеры/коннекты (см. выше).
