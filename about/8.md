# Техническое задание: Обработка Ошибок и Биллинг

**Контекст:** Микросервис должен быть предсказуемым. Любая нештатная ситуация (от падения сети до невалидного JSON от LLM) должна приводить к формированию стандартизированного сообщения об ошибке в `ai-results-queue`. Кроме того, для монетизации SaaS необходимо точно извлекать информацию о потраченных токенах (`usage`) из ответов Dify (особенно из этапа Генерации в External RAG) и обогащать её данными о модели.

**Цель:** Реализовать утилиты для централизованного форматирования ошибок (`ErrorHandler`) и сервис для процессинга биллинга (`BillingService`), которые будут использоваться во всех воркерах.

## 1\. Утилита Обработки Ошибок (`src/utils/errorHandler.js`)

Необходимо создать модуль, который превращает любые объекты ошибок (JS Error, Axios Error, DifyApiError) в безопасный JSON-пейлоад для отправки клиенту.

**Функциональные требования:**

### 1.1 Функция `normalizeError(error)`

Принимает объект ошибки и возвращает стандартизированную структуру:

JavaScript

    {
      errorCode: 'INTERNAL_ERROR', // Код для машин
      message: 'Something went wrong', // Читаемое сообщение
      originalError: ... // (Опционально, только для логов, не для клиента)
    }

**Логика маппинга:**

1.  **Если `error` instanceof `DifyApiError`:**
    
    -   `errorCode`: Использовать `error.difyCode` (например, `provider_quota_exceeded`) или fallback на `DIFY_API_ERROR`.
        
    -   `message`: Сообщение от Dify.
        
    -   **Важно:** Если `error.difyCode` указывает на отсутствие ресурса (например, `dataset_not_found`, `knowledge_base_not_found`), необходимо выполнить инвалидацию кэша (см. раздел 1.3).
        
2.  **Если ошибка Axios (Network Error/Timeout):**
    
    -   `errorCode`: `NETWORK_ERROR` или `TIMEOUT`.
        
    -   `message`: "Failed to connect to AI provider".
        
3.  **Если ошибка `KbNotFoundError` (наша кастомная):**
    
    -   `errorCode`: `KB_NOT_FOUND`.
        
    -   `message`: "Knowledge base not initialized".
        
4.  **Если `SyntaxError` (ошибка парсинга JSON от LLM):**
    
    -   `errorCode`: `LLM_OUTPUT_PARSE_ERROR`.
        
    -   `message`: "Failed to process AI response".
        
5.  **Остальное:**
    
    -   `errorCode`: `INTERNAL_ERROR`.
        
    -   `message`: "Unknown system error".
        

### 1.2 Функция `createErrorPayload(error, meta)`

Обертка, которая готовит финальный объект для очереди результатов.

-   **Вход:** Объект ошибки и `meta` задачи.
    
-   **Выход:**
    
    JavaScript
    
        {
          status: 'error',
          errorCode: '...', // из normalizeError
          message: '...',   // из normalizeError
          meta: meta        // Критично: всегда возвращать контекст!
        }
    

### 1.3 Функция `handleDifyResourceError(error, orgId)` (Stale Cache Strategy)

_Назначение:_ Обработка специфических ошибок Dify, указывающих на отсутствие ресурса (датасета или базы знаний), с автоматической инвалидацией кэша.

-   **Вход:** Объект ошибки `DifyApiError` и `orgId` организации (если доступен в контексте).
    
-   **Логика:**
    
    1.  Проверить, является ли ошибка `DifyApiError` с кодом, указывающим на отсутствие ресурса:
        
        -   `dataset_not_found`
            
        -   `knowledge_base_not_found`
            
        -   HTTP статус 404 с соответствующим сообщением от Dify
            
    2.  Если условие выполнено и `orgId` доступен:
        
        -   Импортировать `OrganizationService` из `src/services/OrganizationService.js`.
            
        -   Вызвать `OrganizationService.invalidateOrgCache(orgId)`.
            
        -   Логировать событие: `logger.warn('Cache invalidated due to Dify resource error', { orgId, errorCode: error.difyCode })`.
            
    3.  Вернуть нормализованную ошибку через `normalizeError(error)`.
        
-   **Важно:** Эта функция должна вызываться **до** формирования финального ответа об ошибке, чтобы следующий запрос воркера мог автоматически восстановить корректное состояние кэша через механизм Lazy Loading.
    
-   **Интеграция:** Функция должна использоваться в слое `infrastructure/dify` при обработке ответов от Dify API, а также в воркерах при обработке ошибок, связанных с операциями над базами знаний.
    

## 2\. Сервис Биллинга (`src/services/BillingService.js`)

Модуль для извлечения и нормализации данных о потреблении ресурсов.

**Функциональные требования:**

### 2.1 Функция `extractUsage(difyResponse, defaultModel)`

Dify возвращает usage в разных местах в зависимости от типа ответа (Chat vs Workflow). В нашей архитектуре (External RAG) мы в основном используем Workflow для генерации.

-   **Вход:** Полный JSON-ответ от Dify API и (опционально) название модели из конфига как fallback.
    
-   **Логика поиска:**
    
    1.  Проверить `difyResponse.metadata.usage` (стандарт для Chatflow).
        
    2.  Проверить `difyResponse.data.outputs.usage` (иногда встречается в Workflow, зависит от версии Dify).
        
    3.  Если usage не найден -> вернуть `{ total_tokens: 0, model: defaultModel }`.
        
-   **Логика определения модели:**
    
    1.  Искать поле `model_name` внутри metadata.
        
    2.  Если нет -> использовать `defaultModel` (который передается в функцию из конфига воркера, например `gpt-4o-mini`).
        
-   **Выход:**
    
    JavaScript
    
        {
          prompt_tokens: 10,
          completion_tokens: 20,
          total_tokens: 30,
          model: 'gpt-4o'
        }
    

## 3\. Интеграция в Воркеры

_(Пример использования в коде воркеров)_

В блоке `try/catch` каждого процессора (Fast/Slow Lane) использовать эти утилиты:

JavaScript

    try {
      // ... External RAG Logic ...
      // Генерация ответа через Workflow
      const response = await difyApi.runWorkflow(...);
      
      // Извлекаем биллинг из этапа генерации
      // Этап Retrieval (поиск) обычно дешевый или бесплатный (зависит от провайдера векторов), 
      // поэтому учитываем токены LLM.
      const usage = BillingService.extractUsage(response, 'gpt-4o-mini');
      
      return resultQueue.add('result', {
        status: 'success',
        data: { text: response.data.outputs.text, ... },
        usage,
        meta: job.data.meta
      });
    } catch (err) {
      logger.error('Job failed', { error: err }); // Логируем оригинал с трейсом
      
      // Обработка ошибок Dify, связанных с отсутствием ресурсов (Stale Cache Strategy)
      // Если ошибка указывает на отсутствие датасета/базы знаний, инвалидируем кэш
      if (err instanceof DifyApiError && job.data.meta?.orgId) {
        ErrorHandler.handleDifyResourceError(err, job.data.meta.orgId);
      }
      
      // Формируем красивую ошибку для клиента
      const payload = ErrorHandler.createErrorPayload(err, job.data.meta);
      
      // Отправляем в очередь результатов (чтобы фронт узнал об ошибке)
      await resultQueue.add('result', payload); 
      
      // Пробрасываем ошибку, чтобы BullMQ пометил задачу как Failed и, возможно, сделал Retry
      throw err; 
    }

# Acceptance Criteria (Критерии приемки)

1.  \[ \] **Маппинг ошибок:** Функция `normalizeError` корректно различает сетевые ошибки, ошибки Dify (`DifyApiError`) и внутренние сбои, выдавая разные `errorCode`.
    
2.  \[ \] **Сохранение контекста:** При генерации ошибочного пейлоада поле `meta` сохраняется.
    
3.  \[ \] **Извлечение Usage:** Функция `extractUsage` корректно достает токены из ответа Dify (в первую очередь проверяя формат ответа Workflow).
    
4.  \[ \] **Model Fallback:** Если Dify не вернул название модели, функция подставляет дефолтную модель.
    
5.  \[ \] **Безопасность:** Утилиты не падают, если на вход пришел `null` или `undefined` вместо ошибки/ответа.
    
6.  \[ \] **Инвалидация кэша:** Функция `handleDifyResourceError` корректно определяет ошибки отсутствия ресурсов (dataset_not_found, knowledge_base_not_found) и вызывает инвалидацию кэша через `OrganizationService.invalidateOrgCache`.
    
7.  \[ \] **Восстановление после инвалидации:** После инвалидации кэша следующий запрос через `ensureAdminKb` или `ensureHistoryKb` автоматически создает новую базу или актуализирует данные из Dify.
