# Техническое задание: Инициализация репозитория (Ticket AI Worker)

**Контекст:** Необходимо создать пустой Node.js проект для микросервиса `ticket-ai-worker`. Проект будет развиваться как долгоживущий production-ready сервис. Архитектура должна строго соответствовать утвержденной структуре (Clean Architecture / Modular Monolith).

**Цель:** Получить полностью настроенный репозиторий с линтерами, форматтерами, структурой папок и базовыми конфигами, готовый к написанию бизнес-логики.

## 1\. Базовая настройка Node.js

1.  **Инициализация:**
    
    -   Выполнить `npm init`.
        
    -   В `package.json` заполнить метаданные:
        
        -   `name`: `ticket-ai-worker`
            
        -   `description`: "AI worker service for processing tickets via Dify (BullMQ/Redis)"
            
        -   `main`: `src/index.js`
            
        -   `type`: `commonjs` (используем `require`, так как это стандарт для Node.js backend, если не оговорено иное, но для совместимости с современными инструментами можно рассмотреть и ESM. _Решение:_ Оставляем CommonJS для максимальной стабильности с BullMQ и Redis, но код пишем чисто).
            
    -   Указать версию Node.js: добавить поле `engines` с указанием текущей LTS версии (напр., `>=18.0.0`).
        
2.  **Зависимости (Dev):**
    
    -   Установить `nodemon` для локальной разработки.
        
    -   Настроить скрипт `dev`: `nodemon src/index.js`.
        
    -   Настроить скрипт `start`: `node src/index.js`.
        

## 2\. Структура проекта (File System)

Необходимо создать дерево директорий. Если директория пуста, добавить в нее файл `.gitkeep`.

**Строгая структура:**

    ticket-ai-worker/
    ├── docker/                 # Файлы Docker
    ├── src/
    │   ├── config/             # Конфигурация
    │   ├── core/               # Типы и константы
    │   ├── infrastructure/     # Внешние сервисы
    │   │   ├── redis/
    │   │   ├── dify/
    │   │   └── bullmq/
    │   ├── services/           # Бизнес-логика
    │   ├── workers/            # Обработчики очередей
    │   ├── utils/              # Утилиты (logger)
    │   └── index.js            # Точка входа (создать пустой файл с console.log)
    ├── tests/                  # Тесты
    ├── .env.example            # Пример переменных окружения
    ├── .gitignore
    ├── .editorconfig
    └── README.md
    

## 3\. Настройка Code Style (Linter & Formatter)

1.  **ESLint:**
    
    -   Установить `eslint`.
        
    -   Инициализировать конфиг (рекомендуется `eslint-config-airbnb-base` или `eslint-config-standard`).
        
    -   **Правила:**
        
        -   Обязательно включить правило, запрещающее `console.log` (предупреждение). Использовать только логгер.
            
        -   Запрет неиспользуемых переменных (Error).
            
        -   Единообразный стиль кавычек (Single quotes).
            
2.  **Prettier:**
    
    -   Установить `prettier` и плагин `eslint-config-prettier` (чтобы они не конфликтовали).
        
    -   Создать `.prettierrc`:
        
        -   `semi`: true (точки с запятой).
            
        -   `singleQuote`: true.
            
        -   `tabWidth`: 2.
            
        -   `trailingComma`: "es5".
            
        -   `printWidth`: 100.
            
3.  **Автоматизация:**
    
    -   Добавить скрипты в `package.json`:
        
        -   `"lint"`: "eslint src/\*\*/\*.js"
            
        -   `"lint:fix"`: "eslint src/\*\*/\*.js --fix"
            
        -   `"format"`: "prettier --write src/\*\*/\*.js"
            
4.  **EditorConfig:**
    
    -   Создать файл `.editorconfig` для синхронизации настроек IDE (VS Code, WebStorm).
        
    -   Установить `indent_style = space`, `indent_size = 2`, `end_of_line = lf`.
        

## 4\. Настройка Git

1.  **Инициализация:** Выполнить `git init`.
    
2.  **.gitignore:**
    
    -   Создать файл и добавить исключения:
        
        -   `node_modules/`
            
        -   `.env` (критично!)
            
        -   `.DS_Store`
            
        -   `coverage/`
            
        -   `*.log`
            
        -   `dist/` (если будет сборка)

## 5. Переменные окружения (`.env.example`)
Создать шаблон с новыми ключами безопасности:

```ini
# App
NODE_ENV=development
LOG_LEVEL=info

# Redis
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=change_me_in_prod

# Dify API
DIFY_API_URL=http://localhost/v1
# Ключ с правами Admin/Dataset Operator (для управления базами и поиска)
DIFY_KEY_ADMIN=
# Ключи приложений
DIFY_KEY_CLASSIFIER=
DIFY_KEY_SUMMARIZER=
DIFY_KEY_RESPONSE_WORKFLOW=

# Workers (BullMQ) - Настройки производительности
# Количество одновременных задач для Fast Lane воркера (интерактивные задачи)
WORKER_FAST_LANE_CONCURRENCY=15
# Количество одновременных задач для Slow Lane воркера (фоновые задачи)
WORKER_SLOW_LANE_CONCURRENCY=2

# Healthcheck
# Порт для HTTP-сервера healthcheck эндпоинта
HEALTHCHECK_PORT=3000
    

## 6\. Git Hooks (Husky) - Опционально, но рекомендуется

1.  Установить `husky` и `lint-staged`.
    
2.  Настроить `pre-commit` хук:
    
    -   При попытке коммита запускать линтер только для измененных файлов (`lint-staged`).
        
    -   Это предотвратит попадание "грязного" кода в репозиторий.
