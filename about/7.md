# Техническое задание: Fast Lane Worker - Этап 1: Реализация утилит (Utils First)

**Контекст:** Задача `CMD_GEN_RESPONSE` в `about/8.md` включает в себя поиск, подсчет токенов, обрезку контекста и генерацию. Для эффективной разработки необходимо разбить эту задачу на этапы. Первый этап — создание независимых утилит, которые можно протестировать изолированно.

**Цель:** Создать независимые утилиты для работы с токенами, форматирования истории и парсинга LLM ответов, которые будут использоваться в Fast Lane Worker.

## 1. Задачи реализации

### 1.1 Реализовать `src/utils/tokenCounter.js`

**Назначение:** Утилита для подсчета токенов в тексте с поддержкой различных моделей.

**Функции:**

1.  **`countTokens(text, modelName)`**
    
    -   Подсчет токенов для текста с использованием библиотеки `tiktoken` для моделей OpenAI.
        
    -   Fallback для других моделей (приблизительный подсчет на основе символов или слов).
        
    -   Обработка edge cases: `null`, `undefined`, пустая строка.
        
2.  **`estimateTotalTokens(context, history, query, modelName)`**
    
    -   Суммарный подсчет токенов для всех компонентов (context, history, query).
        
    -   Учет системного промпта (если требуется).
        
    -   Возврат объекта с разбивкой по компонентам: `{ context, history, query, total }`.

**Зависимости:**

-   Библиотека `tiktoken` для точного подсчета токенов OpenAI моделей.
    
-   Конфигурация модели (`config.model.name`).

**Тестирование:**

-   **Unit-тесты** с различными входными данными:
    
    -   Короткий текст (несколько слов).
        
    -   Длинный текст (несколько тысяч символов).
        
    -   Пустая строка.
        
    -   `null` и `undefined`.
        
    -   Текст с различными символами (кириллица, эмодзи, специальные символы).
        
-   Проверка корректности подсчета для разных моделей (gpt-4, gpt-3.5-turbo).

### 1.2 Реализовать `src/utils/historyFormatter.js`

**Назначение:** Утилита для преобразования истории тикета в структурированный формат Markdown.

**Функции:**

1.  **`formatTicketHistory(history)`**
    
    -   Принимает историю в одном из двух форматов:
        
        1.  **Массив сообщений** (предпочтительно):
            
            ```javascript
            [
              { role: 'user', content: 'Здравствуйте, у меня проблема...' },
              { role: 'assistant', content: 'Здравствуйте! Расскажите подробнее...' },
              { role: 'user', content: 'Не могу войти в систему...' }
            ]
            ```
            
        2.  **Строка Markdown** (альтернативный вариант):
            
            ```markdown
            User: Здравствуйте, у меня проблема...
            
            Assistant: Здравствуйте! Расскажите подробнее...
            
            User: Не могу войти в систему...
            ```
            
    -   Преобразует массив в структурированный Markdown формат:
        
        ```markdown
        User: Здравствуйте, у меня проблема...
        
        Assistant: Здравствуйте! Расскажите подробнее...
        
        User: Не могу войти в систему...
        ```
        
    -   Если передан уже отформатированный Markdown, валидирует его структуру и возвращает как есть (или нормализует форматирование).
        
    -   Обработка некорректных данных: `null`, `undefined`, пустой массив, некорректный формат.

**Зависимости:**

-   Нет (или минимальные).

**Тестирование:**

-   **Unit-тесты** для:
    
    -   Преобразования массива сообщений в Markdown.
        
    -   Проверки уже отформатированного Markdown (валидация структуры).
        
    -   Обработки некорректных данных:
        
        -   `null` и `undefined`.
            
        -   Пустой массив.
            
        -   Массив с некорректной структурой (отсутствие `role` или `content`).
            
        -   Некорректный формат Markdown строки.

### 1.3 Реализовать `src/utils/llmParser.js`

**Назначение:** Утилита для очистки JSON ответов от Markdown оберток, которые могут добавлять LLM.

**Функции:**

1.  **`cleanLlmJson(text)`**
    
    -   Удаление Markdown оберток (например, `\`\`\`json ... \`\`\``).
        
    -   Удаление лишних пробелов и переносов строк.
        
    -   Валидация JSON структуры после очистки.
        
    -   Возврат очищенного JSON или выброс ошибки при некорректном формате.

**Зависимости:**

-   Нет (или минимальные).

**Тестирование:**

-   **Unit-тесты** с различными форматами оберток:
    
    -   JSON в обертке `\`\`\`json ... \`\`\``.
        
    -   JSON в обертке `\`\`\` ... \`\`\``.
        
    -   JSON без оберток.
        
    -   Некорректный JSON (должен выбросить ошибку).
