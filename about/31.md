# План стандартизации формата запросов и ответов

## Цель
Привести все запросы и ответы к единому стандартизированному формату (Standardized Envelope), чтобы упростить интеграцию для разработчиков и устранить необходимость в множественных `if/else` для обработки разных типов ответов.

---

## Текущие проблемы

### 1. Разный нейминг входных полей
- `targetLanguage` (CMD_ANALYZE_NEW_TICKET)
- `targetLang` (CMD_TRANSLATE)
- `lang` (CMD_GEN_RESPONSE, CMD_ARCHIVE_TICKET)

### 2. Разная структура `data` в ответе
- Обычно объект: `{ title: ..., sentiment: ... }`
- В `CMD_KB_LIST_FILES` массив: `[...]`
- В ошибках: `{ status: "error", ... }`

### 3. Смешивание данных и мета-информации
- Поле `usage` (токены) лежит внутри `data`, что мешает парсингу чистых бизнес-данных

### 4. Разные названия идентификаторов
- `fileId` (CMD_KB_ADD_FILE)
- `docId` (CMD_ARCHIVE_TICKET)
- `documentId` (в некоторых местах)

### 5. Разные форматы ошибок
- `{ status: "error", errorCode: ..., message: ... }`
- Нет единой структуры с `success: false`

## Целевая структура

### 1. Единый формат запроса (Request Envelope)

```typescript
interface StandardRequest {
  action: string;              // Имя команды (CMD_*)
  meta?: {                     // Метаданные (контекст)
    traceId?: string;
    orgId?: string;
    [key: string]: any;        // Дополнительные метаданные
  };
  payload: {                   // Бизнес-данные
    content?: string;          // Универсальное название для текста
    params?: {                 // Опциональные настройки
      targetLang?: string;     // Унифицированное название
      [key: string]: any;
    };
    [key: string]: any;         // Дополнительные поля команды
  };
}
```

**Пример:**
```json
{
  "action": "CMD_ANALYZE_NEW_TICKET",
  "meta": {
    "traceId": "760525b8-...",
    "orgId": "org-123"
  },
  "payload": {
    "content": "У меня не работает вход в систему",
    "params": {
      "targetLang": "ru"
    }
  }
}
```

### 2. Единый формат ответа (Response Envelope)

```typescript
interface StandardResponse<T> {
  success: boolean;            // Всегда true или false
  meta: {
    traceId: string;
    timestamp: number;
    jobId: string;
    processingTimeMs?: number;
    usage?: {                  // Выносим токены сюда
      prompt_tokens: number;
      completion_tokens: number;
      total_tokens: number;
      model?: string;
      stages?: Array<{
        prompt_tokens: number;
        completion_tokens: number;
        model?: string;
        type?: string;
      }>;
    };
  };
  data?: T;                    // Данные (только если success: true)
  error?: {                   // Ошибка (только если success: false)
    code: string;
    message: string;
    details?: any;
    retryable?: boolean;
  };
}
```

**Пример успешного ответа:**
```json
{
  "jobName": "CMD_ANALYZE_NEW_TICKET",
  "result": {
    "success": true,
    "meta": {
      "traceId": "760525b8-...",
      "timestamp": 1699123456789,
      "jobId": "job-123",
      "processingTimeMs": 3290,
      "usage": {
        "total_tokens": 234,
        "prompt_tokens": 214,
        "completion_tokens": 20,
        "model": "gpt-4",
        "stages": [
          {
            "prompt_tokens": 214,
            "completion_tokens": 20,
            "model": "gpt-4"
          }
        ]
      }
    },
    "data": {
      "title": "Ошибка 500 при входе",
      "sentiment": "negative",
      "tags": ["bug", "auth"]
    }
  }
}
```

**Пример ошибки:**
```json
{
  "jobName": "CMD_UNKNOWN_COMMAND",
  "result": {
    "success": false,
    "meta": {
      "traceId": "760525b8-...",
      "timestamp": 1699123456789,
      "jobId": "job-123"
    },
    "error": {
      "code": "UNKNOWN_COMMAND",
      "message": "Command 'CMD_BLAH' is not registered",
      "retryable": false
    }
  }
}
```

### 3. Специфичные изменения по командам

#### A. CMD_KB_LIST_FILES - обертка массивов

**Было:**
```json
{
  "success": true,
  "data": [
    { "id": "1", "name": "file1.md" },
    { "id": "2", "name": "file2.md" }
  ]
}
```

**Стало:**
```json
{
  "success": true,
  "data": {
    "items": [
      { "id": "1", "name": "file1.md" },
      { "id": "2", "name": "file2.md" }
    ],
    "count": 2
  }
}
```

#### B. Унификация полей текстовых результатов

- `text` → `content` (для основного текстового результата)
- `original` → `sourceContent` (для исходного текста в переводе)
- `translated` → `content` (для переведенного текста)

**Пример для CMD_TRANSLATE:**
```json
{
  "success": true,
  "data": {
    "content": "Добро пожаловать...",
    "sourceContent": "Welcome...",
    "targetLang": "ru"
  }
}
```

#### C. Унификация идентификаторов

- `fileId` / `docId` → `documentId` (везде)

**Пример для CMD_KB_ADD_FILE:**
```json
{
  "success": true,
  "data": {
    "documentId": "8a14e64e-...",
    "status": "indexing"
  }
}
```

## Обратная совместимость

### Стратегия миграции

1. **Фаза 1: Поддержка обоих форматов (2 недели)**
   - Старый формат продолжает работать
   - Новый формат доступен через флаг или версию API

2. **Фаза 2: Переход на новый формат (1 неделя)**
   - По умолчанию используется новый формат
   - Старый формат доступен через флаг `legacy: true`

3. **Фаза 3: Удаление старого формата (после уведомления)**
   - Удаление поддержки старого формата
   - Обновление документации

### Адаптеры для обратной совместимости

Создать `src/utils/legacyAdapter.js`:
- `adaptRequestToLegacy(request)` - преобразование нового формата в старый
- `adaptResponseFromLegacy(response)` - преобразование старого формата в новый

## Примеры кода

### До стандартизации (CMD_ANALYZE_NEW_TICKET)

```javascript
const result = {
  success: true,
  data: {
    title: parsed.title,
    sentiment: parsed.sentiment.toLowerCase(),
    usage: {
      model: usage.model,
      stages: [{
        prompt_tokens: usage.prompt_tokens,
        completion_tokens: usage.completion_tokens,
        model: usage.model,
      }],
    },
  },
};

await sendResult('CMD_ANALYZE_NEW_TICKET', result, meta);
```

### После стандартизации

```javascript
const startTime = Date.now(); // В начале обработчика

// ... обработка ...
```
