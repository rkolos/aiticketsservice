# Техническое задание: Реализация Hybrid Search и Reranking (Jina)

**Контекст:** Для повышения качества ответов поддержки необходимо использовать передовые методы поиска (RAG). Простой векторный поиск часто упускает ключевые слова, а поиск по ключевым словам не улавливает смысл. Гибридный поиск (Hybrid Search) объединяет оба подхода, а Reranking (переранжирование) с использованием модели Jina позволяет отобрать наиболее релевантные фрагменты.

**Цель:** Реализовать в микросервисе механизм предварительного поиска контекста в базе знаний Dify с использованием параметров `hybrid_search` и `jina-reranker-v2-base-multilingual` перед генерацией ответа LLM.

## 1\. Обновление Dify Client (`src/infrastructure/dify/api.js`)

Необходимо добавить метод для прямого взаимодействия с API поиска (Retrieval API).

**Требования:**

1.  Метод `retrieve(datasetId, query, config)`.
    
2.  Используемый эндпоинт: `POST /datasets/{dataset_id}/retrieve`.
    
3.  **Важно:** Правильная структура payload для версии API v1, чтобы избежать ошибки 400.
    

**Спецификация метода:**

JavaScript

    /**
     * Выполняет поиск чанков в датасете с поддержкой Hybrid Search и Rerank.
     * * @param {string} datasetId - UUID датасета.
     * @param {string} query - Текст запроса.
     * @param {object} [retrievalConfig] - Переопределение настроек поиска.
     */
    async retrieve(datasetId, query, retrievalConfig = {}) {
      // Базовая конфигурация для Jina Reranker
      const defaultModel = {
        search_method: 'hybrid_search',
        reranking_enable: true,
        reranking_mode: 'reranking_model', // Обязательный параметр режима
        reranking_model: {
          reranking_provider_name: 'jina',
          reranking_model_name: 'jina-reranker-v2-base-multilingual'
        },
        weights: 0.7, // Приоритет семантики (0.7) над ключевыми словами
        top_k: 5,
        score_threshold_enabled: true,
        score_threshold: 0.5
      };
    
      const payload = {
        query: query,
        retrieval_model: { ...defaultModel, ...retrievalConfig }
      };
    
      return this.post(`/datasets/${datasetId}/retrieve`, payload);
    }

## 2\. Доработка Fast Lane Worker (`src/workers/fastLaneProcessor.js`)

Необходимо интегрировать шаг поиска контекста в процесс обработки задачи `CMD_GEN_RESPONSE`.

**Алгоритм действий (внутри функции процессора):**

1.  **Определение ID базы знаний:** Получить `adminKbId` для текущей организации через `OrganizationService`.
    
2.  **Retrieval Step (Поиск):**
    
    -   Если `adminKbId` существует, вызвать `difyApi.retrieve`.
        
    -   Использовать `try/catch`. Если поиск упал (например, не настроен API ключ Jina в Dify), логировать `warn`, но **не прерывать** выполнение задачи.
        
3.  **Формирование контекста:**
    
    -   Извлечь массив `records` из ответа.
        
    -   Склеить сегменты в одну строку (например, через `\n\n`).
        
    -   Можно добавлять метаданные скора: `[Score: 0.85] Text...`.
        
4.  **Передача в Workflow:**
    
    -   Передать полученную строку в переменную `context` при вызове `difyApi.runWorkflow`.
        

**Пример логики:**

JavaScript

    // ... import OrganizationService ...

## 3\. Требования к инфраструктуре

1.  **Тип индексации:** Убедиться, что `FileService` создает документы с `indexing_technique: 'high_quality'` (уже реализовано, проверить отсутствие регрессии). Гибридный поиск не работает на Economy индексе.
    
2.  **Настройки Dify:** В Dify (в панели администратора) должен быть добавлен API ключ провайдера **Jina**. Если ключа нет, API вернет ошибку (которую мы должны обработать как `warn`).
    

## 4\. Acceptance Criteria (Критерии приемки)

1.  \[ \] **Метод API:** В классе `DifyClient` реализован метод `retrieve` с корректной структурой JSON (объекты `reranking_model`).
    
2.  \[ \] **Интеграция:** В логах `fastLaneProcessor` при обработке запроса появляется запись вида `Retrieved X chunks via Hybrid Search`.
    
3.  \[ \] **Отказоустойчивость:** Если поиск падает (ошибка 400, 500, неверный ключ Jina), бот все равно отвечает (используя только историю и знания модели), задача не падает в `Failed`.
    
4.  \[ \] **Качество:** Контекст, передаваемый в промпт LLM, содержит наиболее релевантные фрагменты из базы знаний.
