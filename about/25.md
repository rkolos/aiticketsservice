# Техническое задание: Единая входная очередь и Router Worker

**Контекст:** В текущей архитектуре внешние сервисы должны знать, в какую из двух очередей (`interactive` или `background`) отправлять задачу в зависимости от её типа. Это нарушает инкапсуляцию и усложняет интеграцию.

**Цель:** Создать единую входную очередь `ai-entry-queue` для всех входящих задач. Реализовать легковесный **Router Worker**, который будет мгновенно разбирать задачи из входной очереди и распределять их по внутренним очередям (Fast/Slow) на основе типа команды (`job.name`).

## 1\. Изменения в архитектуре очередей

### 1.1 Новая константа очереди

В `src/core/constants.js` добавить новую очередь:

JavaScript

    module.exports = {
      QUEUES: {
        ENTRY: 'ai-entry-queue',          // <--- Новая единая точка входа
        INTERACTIVE: 'ai-interactive-queue',
        BACKGROUND: 'ai-background-queue',
        RESULTS: 'ai-results-queue',
      },
    };

### 1.2 Логика маршрутизации

Необходимо определить маппинг команд к очередям.

**Fast Lane (`INTERACTIVE`):**

-   `CMD_ANALYZE_NEW_TICKET`
    
-   `CMD_GEN_RESPONSE`
    
-   `CMD_TRANSLATE`
    
-   `CMD_KB_LIST_FILES`
    
-   `CMD_KB_DELETE_FILE`
    

**Slow Lane (`BACKGROUND`):**

-   `CMD_KB_ADD_FILE`
    
-   `CMD_ARCHIVE_TICKET`
    
-   `CMD_SYS_RESYNC_CACHE`
    
-   `CMD_CLEANUP_ORG`
    

## 2\. Реализация Router Worker

Этот воркер не выполняет бизнес-логику Dify. Его задача — только перекладывание (Relay).

### 2.1 Файл `src/workers/routerProcessor.js`

Создать процессор, который:

1.  Получает джоб.
    
2.  Читает `job.name` (тип команды).
    
3.  Определяет целевую очередь (Fast или Slow).
    
4.  Добавляет задачу в целевую очередь с теми же данными (`data`) и опциями.
    

**Важные требования:**

-   **Сохранение данных:** Поля `data`, `meta` (и `lang`, если он есть) должны быть переданы без изменений.
    
-   **Имя задачи:** Должно сохраниться (`job.name`).
    
-   **Скорость:** Этот воркер должен работать максимально быстро.
    

**Пример логики:**

JavaScript

    const { QUEUES } = require('../core/constants');
    const { Queue } = require('bullmq');
    // Инициализировать очереди (важно переиспользовать соединения если возможно, или создавать новые через фабрику)
    // ...
    
    const fastQueue = new Queue(QUEUES.INTERACTIVE, { connection: ... });
    const slowQueue = new Queue(QUEUES.BACKGROUND, { connection: ... });
    
    const FAST_COMMANDS = [
      'CMD_GEN_RESPONSE', 'CMD_ANALYZE_NEW_TICKET', 'CMD_TRANSLATE', 
      'CMD_KB_LIST_FILES', 'CMD_KB_DELETE_FILE'
    ];
    
    module.exports = async function routerProcessor(job) {
      const { name, data } = job;
      
      if (FAST_COMMANDS.includes(name)) {
        await fastQueue.add(name, data);
      } else {
        // Всё остальное по умолчанию в Slow, либо явная проверка
        await slowQueue.add(name, data);
      }
      
      return { status: 'routed', to: FAST_COMMANDS.includes(name) ? 'fast' : 'slow' };
    };

### 2.2 Инициализация в `src/infrastructure/bullmq/index.js`

1.  В функции `initWorkers` добавить инициализацию `routerWorker`.
    
2.  Использовать фабрику `createWorker`.
    
3.  **Настройки Router Worker:**
    
    -   Очередь: `QUEUES.ENTRY`.
        
    -   Concurrency: Высокое (например, 50-100), так как операций ввода-вывода нет, только перекладывание в Redis. Это не нагружает CPU или Dify.

## 4\. Acceptance Criteria (Критерии приемки)

1.  \[ \] **Единая точка входа:** При отправке любой поддерживаемой задачи (`CMD_GEN_RESPONSE`, `CMD_ARCHIVE_TICKET` и т.д.) в очередь `ai-entry-queue`, она корректно обрабатывается.
    
2.  \[ \] **Маршрутизация:**
    
    -   Задачи типа `CMD_GEN_RESPONSE` попадают в `fastLaneWorker`.
        
    -   Задачи типа `CMD_ARCHIVE_TICKET` попадают в `slowLaneWorker`.
        
3.  \[ \] **Сохранность данных:** Все поля payload (включая новый параметр `lang`) доходят до конечного воркера без изменений.
    
4.  \[ \] **Прозрачность:** Результат выполнения задачи по-прежнему попадает в `ai-results-queue`, и Main App получает ответ, как и раньше.
