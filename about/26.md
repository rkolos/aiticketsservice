# Техническое задание: Смок-тестирование (E2E Emulation)

**Контекст:** После внедрения **Router Worker** и единой точки входа (`ai-entry-queue`), а также добавления параметра `lang`, необходимо удостовериться, что вся цепочка обработки сообщений работает корректно. Ручное тестирование через Redis CLI или GUI неудобно и не дает гарантий работоспособности всех сценариев.

**Цель:** Создать скрипт `scripts/smoke-test.js`, который эмулирует поведение внешнего сервиса (Main App). Скрипт должен последовательно отправить задачи всех типов в единую очередь, дождаться обработки и вывести читаемый лог взаимодействия ("Запрос -> Ожидание -> Ответ").

## 1\. Требования к скрипту

### 1.1 Стек и Зависимости

-   Язык: Node.js.
    
-   Библиотеки: `bullmq`, `ioredis`, `dotenv`, `uuid` (для генерации уникальных ID запросов).
    
-   Конфигурация: Использовать переменные из `.env` для подключения к Redis.
    

### 1.2 Архитектура теста

Скрипт должен состоять из двух независимых компонентов, работающих параллельно:

1.  **Producer (Эмулятор Main App):** Отправляет задачи в `ai-entry-queue`.
    
2.  **Consumer (Эмулятор Main App Listener):** Слушает `ai-results-queue` и сопоставляет ответы с запросами.
    

**Механизм корреляции:** Использовать поле `meta.traceId`. При отправке генерировать UUID, при получении — проверять его наличие.

## 2\. Сценарии тестирования (Test Cases)

Скрипт должен прогнать следующие сценарии. Между тестами делать небольшую паузу (1-2 сек), чтобы логи были читаемыми.

### 2.1 Fast Lane (Интерактивные задачи)

1.  **Анализ тикета (`CMD_ANALYZE_NEW_TICKET`)**
    
    -   _Payload:_ `{ text: "У меня не работает вход в систему, ошибка 500", targetLanguage: "ru" }`
        
    -   _Ожидание:_ Ответ содержит `title` и `sentiment`.
        
2.  **Генерация ответа (`CMD_GEN_RESPONSE`) + Lang Check**
    
    -   _Payload:_ `{ query: "Как восстановить пароль?", history: [...], lang: "en" }`
        
    -   _Ожидание:_ Успешный статус, текст ответа (желательно проверить, что он на английском, но достаточно факта наличия текста), наличие `usage`.
        
3.  **Перевод (`CMD_TRANSLATE`)**
    
    -   _Payload:_ `{ text: "Hello world", targetLang: "ru" }`
        
    -   _Ожидание:_ Текст содержит кириллицу.
        

### 2.2 Slow Lane (Фоновые задачи)

4.  **Загрузка файла (`CMD_KB_ADD_FILE`)**
    
    -   _Payload:_ Ссылка на публичный стабильный файл (например, логотип Google или текстовый файл из GitHub gist), `fileName: "test.txt"`.
        
    -   _Ожидание:_ Статус `indexing` или `completed`, наличие `fileId`.
        
5.  **Архивация тикета (`CMD_ARCHIVE_TICKET`)**
    
    -   _Payload:_ Массив истории сообщений.
        
    -   _Ожидание:_ Наличие `summary`, `docId`.

## 4\. Логика реализации

### 4.1 Функция `runTest(jobName, data, validator)`

Создать функцию-обертку, которая:

1.  Генерирует `traceId`.
    
2.  Добавляет задачу в очередь `ai-entry-queue`.
    
3.  Возвращает `Promise`, который резолвится, когда в очереди результатов появляется сообщение с этим `traceId`.
    
4.  Включает тайм-аут (например, 30 секунд), чтобы тест не висел вечно, если воркер упал.
    
5.  Вызывает функцию `validator(result)` для проверки содержимого ответа.
    

### 4.2 Обработка ошибок

-   Если тайм-аут истек — тест провален (`❌ TIMEOUT`).
    
-   Если статус ответа `error` — тест провален (`❌ WORKER ERROR: ...message`).
    
-   Если валидатор вернул `false` — тест провален (`❌ VALIDATION FAILED`).
    

## 5\. Интеграция

Добавить команду в `package.json`:

JSON

    "test:smoke": "node scripts/smoke-test.js"

# Acceptance Criteria (Критерии приемки)

1.  \[ \] Скрипт `scripts/smoke-test.js` создан и запускается.
    
2.  \[ \] Скрипт использует **только** очередь `ai-entry-queue` для отправки.
    
3.  \[ \] Проходят проверки для 5 основных типов задач (Анализ, Генерация, Перевод, Файл, Архивация).
    
4.  \[ \] Проверяется передача параметра `lang` (ответ приходит).
    
5.  \[ \] Логирование соответствует формату: видно, что отправлено, что получено, и вердикт.
    
6.  \[ \] Скрипт корректно завершает работу (закрывает соединения Redis) после выполнения всех тестов.
