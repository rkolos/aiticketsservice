# Техническое задание: Экспорт контекста RAG в результат генерации

**Контекст:** В текущей реализации при выполнении задачи `CMD_GEN_RESPONSE` микросервис выполняет поиск в базе знаний (RAG) и формирует ответ LLM. Однако внешний сервис (Main App) получает только итоговый текст ответа. Для целей отладки, прозрачности и отображения источников пользователю (цитирование) необходимо возвращать найденные фрагменты данных вместе с ответом.

**Цель:** Модифицировать `fastLaneProcessor` так, чтобы сырые данные контекста (найденные чанки, их скор релевантности и метаданные), полученные на этапе `retrieve`, добавлялись в итоговый JSON-ответ в очередь `ai-results-queue`.

## 1\. Изменение структуры ответа (Output Contract)

Необходимо расширить объект результата выполнения задачи `CMD_GEN_RESPONSE`.

**Текущий ответ (пример):**

JSON

    {
      "answer": "Текст ответа...",
      "usage": { "total_tokens": 150 }
    }

**Новый формат ответа:**

JSON

    {
      "answer": "Текст ответа...",
      "usage": { "total_tokens": 150 },
      "retrievedContext": [
        {
          "content": "Текст чанка из базы...",
          "score": 0.85,
          "segment": { ... }, // Метаданные сегмента из Dify
          "document": { ... } // Метаданные документа (имя файла и т.д.)
        },
        ...
      ]
    }

Если контекст не найден или поиск не выполнялся, поле `retrievedContext` должно быть пустым массивом `[]`.

## 2\. Доработка Fast Lane Worker (`src/workers/fastLaneProcessor.js`)

Необходимо изменить логику обработки `CMD_GEN_RESPONSE`. Сейчас контекст формируется в строку и сразу "забывается" как объект. Нужно сохранить сырой массив записей.

**Алгоритм:**

1.  Создать переменную `retrievedRecords` со значением `[]` по умолчанию.
    
2.  В блоке поиска (`difyApi.retrieve`):
    
    -   При успешном получении ответа сохранить `result.records` в переменную `retrievedRecords`.
        
    -   Логику склеивания строки `contextString` для промпта оставить без изменений (строить её на основе `retrievedRecords`).
        
3.  В блоке возврата результата (`return`):
    
    -   Добавить поле `retrievedContext: retrievedRecords`.
        

**Пример реализации:**

JavaScript

    // ... внутри функции процессора
    let contextString = '';
    let retrievedRecords = []; // <--- Хранилище сырых данных
    
    // ЭТАП: Поиск (Retrieval)
    if (orgKbId) {
        try {
            const retrievalResult = await difyApi.retrieve(orgKbId, query, { top_k: 5 });
            
            if (retrievalResult && retrievalResult.records) {
                 retrievedRecords = retrievalResult.records; // Сохраняем массив
                 
                 // Формируем строку для LLM (как и раньше)
                 contextString = retrievedRecords
                    .map(r => `[Score: ${r.score}] ${r.segment.content}`)
                    .join('\n\n');
            }
        } catch (error) {
            logger.warn(`Retrieval failed: ${error.message}`);
            // retrievedRecords остается []
        }
    }
    
    // ... Вызов LLM ...
    const result = await difyApi.runWorkflow(key, { ...inputs, context: contextString }, user);
    
    // ... Формирование ответа ...
    return {
        answer: result.data.outputs.text,
        usage: result.data.usage,
        retrievedContext: retrievedRecords // <--- Возвращаем во внешний мир
    };

## 3\. Обновление Smoke Test (`scripts/smoke-test.js`)

Необходимо убедиться, что новый функционал работает и данные реально приходят.

**Сценарий:** `CMD_GEN_RESPONSE` **Проверка:**

1.  Выполнить запрос, который заведомо должен найти что-то в базе знаний (использовать уже загруженные данные из предыдущих шагов теста).
    
2.  В ответе (`result`) проверить наличие поля `retrievedContext`.
    
3.  Убедиться, что `retrievedContext` является массивом (`Array.isArray`).
    
4.  _(Опционально)_ Вывести в лог количество найденных чанков: `Found chunks: ${result.retrievedContext.length}`.
    

## 4\. Acceptance Criteria (Критерии приемки)

1.  \[ \] **Поле в ответе:** Любой успешный ответ на `CMD_GEN_RESPONSE` содержит поле `retrievedContext` (массив).
    
2.  \[ \] **Состав данных:** В массиве содержатся объекты с полями `score` и `content` (структура соответствует ответу Dify API `/retrieve`).
    
3.  \[ \] **Пустой контекст:** Если база знаний пуста или ничего не найдено, возвращается пустой массив `[]`, а не `undefined` или `null`.
    
4.  \[ \] **Отсутствие регрессии:** Логика генерации ответа LLM не сломана (контекст по-прежнему передается в промпт в виде строки).
