# Техническое задание: HTTP Клиент для Dify API

**Контекст:** Микросервис должен активно взаимодействовать с внешним API платформы Dify для выполнения задач (запуск Workflow, чат, управление датасетами, поиск контекста). Нам нужен централизованный, надежный HTTP-клиент с логированием, обработкой ошибок и типизированными методами.

**Цель:** Реализовать модуль `src/infrastructure/dify` на базе библиотеки `axios`. Модуль должен состоять из низкоуровневого клиента (`client.js`) и высокоуровневых методов API (`api.js`).

## 1\. Установка зависимостей

-   `axios`: HTTP-клиент.
    
-   `form-data`: Для формирования `multipart/form-data` при загрузке файлов (обязательно для Node.js среды).
    

## 2\. Низкоуровневый клиент (`src/infrastructure/dify/client.js`)

Создать настроенный инстанс Axios.

**Требования:**

1.  **Base URL:** Брать из конфига (`config.dify.url`).
    
2.  **Timeout:** Установить разумный таймаут (например, 60 секунд), так как LLM могут отвечать долго.
    
3.  **Ограничения размера тела запроса:**
    
    -   Установить `maxBodyLength: Infinity` и `maxContentLength: Infinity` в конфигурации Axios.
        
    -   **Причина:** Axios имеет дефолтное ограничение (обычно 10-15 МБ) на размер тела запроса и ответа. При загрузке больших файлов (например, PDF размером 50 МБ) сервис будет падать с ошибкой, если эти ограничения не сняты.
        
    -   **Важно:** Эти настройки должны быть установлены на уровне инстанса Axios, чтобы применяться ко всем запросам через этот клиент.
        
4.  **Интерцепторы (Interceptors):**
    
    -   **Request:** Логировать исходящий запрос (Method, URL).
        
        -   _Важно:_ **Не логировать заголовки (Headers)**, чтобы избежать утечки API-ключей.
            
        -   Не логировать тело запроса, если оно содержит бинарные данные или большие файлы.
            
    -   **Response Success:** Логировать статус ответа (200 OK) и время выполнения (duration).
        
    -   **Response Error:** Логировать ошибку (Status code, URL).
        
4.  **Обработка ошибок:**
    
    -   Если Dify возвращает ошибку (4xx, 5xx), интерцептор должен выбрасывать кастомную ошибку `DifyApiError`, сохраняя детали из ответа Dify (поле `code` и `message` из JSON тела).
        

## 3\. Методы API (`src/infrastructure/dify/api.js`)

Реализовать набор функций, которые инкапсулируют эндпоинты Dify. _Все методы должны быть асинхронными и принимать `apiKey` первым аргументом (dependency injection для поддержки разных ключей/клиентов)._

**Список необходимых методов:**

### Группа 1: Workflow & Chat

_Эти методы используют API-ключи конкретных приложений (App Keys: Classifier, Summarizer, Helper)._

1.  **`runWorkflow(apiKey, inputs, user)`**
    
    -   _Method:_ `POST /workflows/run`
        
    -   _Body:_ `{ inputs, response_mode: "blocking", user }`
        
    -   _Return:_ Объект с результатами (`data.outputs`).
        
    -   _Применимость:_ Используется для генерации ответов, суммаризации и классификации.
        
2.  **`sendChatMessage(apiKey, query, inputs, user, conversationId)`**
    
    -   _Method:_ `POST /chat-messages`
        
    -   _Body:_ `{ query, inputs, response_mode: "blocking", user, conversation_id }`
        
    -   _Return:_ Полный ответ (включая `metadata.usage`).
        

### Группа 2: Управление Датасетами (Knowledge Base)

_Эти методы требуют ключ с правами **Dataset Operator** или **Admin** (см. `config.dify.keys.admin`). Ключи обычных приложений здесь не подойдут._

3.  **`listDatasets(apiKey, page, limit)`**
    
    -   _Method:_ `GET /datasets`
        
    -   _Query:_ `?page={page}&limit={limit}`
        
    -   _Return:_ Массив датасетов и метаданные пагинации.
        
4.  **`createDataset(apiKey, name)`**
    
    -   _Method:_ `POST /datasets`
        
    -   _Body:_ `{ name, permission: "only_me" }` (или актуальные поля для вашей версии Dify).
        
    -   _Return:_ Объект созданного датасета (с `id`).
        
5.  **`deleteDataset(apiKey, datasetId)`**
    
    -   _Method:_ `DELETE /datasets/{datasetId}`
        
    -   _Return:_ Результат удаления (обычно пустой объект или статус).
        
    -   _Применимость:_ Используется для очистки ресурсов организации при удалении (`CMD_CLEANUP_ORG`).
        
    -   _Обработка ошибок:_ Если датасет не существует (404), это не критическая ошибка — метод должен обработать это gracefully.
        

### Группа 3: Работа с документами и Поиск (Retrieval)

_Также используют `DIFY_KEY_ADMIN`._

6.  **`createDocumentByText(apiKey, datasetId, name, text)`**
    
    -   _Method:_ `POST /datasets/{datasetId}/document/create_by_text`
        
    -   _Body:_ Стандартный пейлоад Dify для текста (indexing\_technique, process\_rule).
        
    -   _Return:_ Результат создания.
        
7.  **`uploadFile(apiKey, datasetId, fileStream, fileName, user = 'system', fileSize = null)`**
    
    -   _Method:_ `POST /datasets/{datasetId}/document/create_by_file`
        
    -   _Body:_ `FormData`.
        
        -   Поле `file`: поток (`fileStream`) с обязательным указанием `filename: fileName` в опциях `form-data`.
            
            -   **Важно:** Если передан параметр `fileSize` (размер файла в байтах), необходимо указать его в опциях `form-data` как `knownLength`. Это предотвратит использование `Transfer-Encoding: chunked`, которое некоторые серверы (или Nginx перед Dify) могут не принимать при загрузке файлов.
                
            -   Пример: `formData.append('file', fileStream, { filename: fileName, knownLength: fileSize })`.
                
        -   Поле `data`: JSON строка с правилами индексации (process\_rule, indexing\_technique).
            
    -   _Headers:_ Заголовки от `formData.getHeaders()` (для Boundary).
        
    -   _Примечание:_ 
        
        -   Аргумент `user` опционален, по умолчанию `'system'`.
            
        -   Аргумент `fileSize` опционален. Если не передан, `form-data` будет использовать chunked-кодирование. Рекомендуется всегда передавать размер файла, если он известен (например, из заголовка `content-length` при скачивании).
            
8.  **`listDocuments(apiKey, datasetId, page, limit)`**
    
    -   _Method:_ `GET /datasets/{datasetId}/documents`
    
9.  **`deleteDocument(apiKey, datasetId, documentId)`**
    
    -   _Method:_ `DELETE /datasets/{datasetId}/documents/{documentId}`
    
10. **`retrieveChunks(apiKey, datasetId, query, limit = 5)`** _(External RAG)_
    
    -   _Назначение:_ Поиск релевантных сегментов текста в базе знаний. Используется воркером перед генерацией ответа.
        
    -   _Method:_ `POST /datasets/{datasetId}/retrieve`
        
    -   _Body:_
        
        JSON
        
            {
              "query": "Текст запроса",
              "retrieval_model": {
                "search_method": "hybrid",
                "rerun_model": null,
                "top_k": limit,
                "score_threshold_enabled": false
              }
            }
        
    -   _Return:_ Promise c массивом найденных сегментов (records/chunks) с их контентом и скором релевантности.
        

## 4\. Кастомные ошибки (`src/core/errors.js`)

Создать класс `DifyApiError` (наследуется от `Error`).

-   Поля: `statusCode`, `difyCode` (код ошибки от самого Dify, например `dataset_not_initialized`), `url`.
    
-   Использовать этот класс в интерцепторе Axios при обработке ошибок.
