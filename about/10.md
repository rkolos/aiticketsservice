# Техническое задание: Organization Service - Этап 2: Synchronization (Warm-up)

**Контекст:** Модуль `OrganizationService` в `about/7.md` отвечает за синхронизацию, ленивую загрузку и инвалидацию кэша. На втором этапе реализуется полная синхронизация Redis с состоянием Dify при старте приложения (Cache Warming).

**Цель:** Реализовать метод `syncCacheWithDify`, который синхронизирует все датасеты из Dify с Redis, используя пагинацию и парсинг имен по конвенции. Включить этот вызов в `index.js` для автоматической синхронизации при старте.

## 1. Задачи реализации

### 1.1 Реализовать `syncCacheWithDify()` (Cache Warming)

**Назначение:** Полная синхронизация Redis с состоянием Dify. Используется при старте и для ручного сброса.

**Метод:**

```javascript
async syncCacheWithDify() {
  // Реализация
}
```

**Алгоритм:**

1.  **Authorization:**
    
    -   Использовать ключ `config.dify.keys.admin` для авторизации запросов к Dify API.
        
2.  **Запросить список датасетов с пагинацией:**
    
    -   Вызвать `difyApi.listDatasets(adminKey, page, limit)` для получения первой страницы.
        
    -   **Важно:** Реализовать **пагинацию**. Если датасетов больше 20/50/100, делать запросы в цикле, пока не будут получены все.
        
    -   Алгоритм пагинации:
        
        ```javascript
        let page = 1;
        let limit = 50; // или из конфига
        let allDatasets = [];
        let hasMore = true;
        
        while (hasMore) {
          const response = await difyApi.listDatasets(adminKey, page, limit);
          allDatasets.push(...response.data);
          
          hasMore = response.data.length === limit && response.has_more !== false;
          page++;
        }
        ```
        
3.  **Перебрать полученный список и парсить имена:**
    
    -   Для каждого датасета проверить имя:
        
        -   Если имя совпадает с паттерном `KB_ADMIN_(.*)` -> извлечь `orgId` из группы, сохранить как `adminKbId`.
            
        -   Если имя совпадает с паттерном `KB_HISTORY_(.*)` -> извлечь `orgId` из группы, сохранить как `historyKbId`.
            
        -   Игнорировать "чужие" датасеты (не соответствующие паттернам).
            
    -   Пример парсинга:
        
        ```javascript
        const adminMatch = dataset.name.match(/^KB_ADMIN_(.+)$/);
        const historyMatch = dataset.name.match(/^KB_HISTORY_(.+)$/);
        
        if (adminMatch) {
          const orgId = adminMatch[1];
          // Сохранить adminKbId для orgId
        } else if (historyMatch) {
          const orgId = historyMatch[1];
          // Сохранить historyKbId для orgId
        }
        ```
        
4.  **Сгруппировать результаты по OrgId:**
    
    -   Создать объект `orgMap`, где ключ — `orgId`, значение — объект с `adminKbId` и `historyKbId`:
        
        ```javascript
        {
          '1': { adminKbId: 'ds-123', historyKbId: 'ds-456' },
          '2': { adminKbId: 'ds-789', historyKbId: null }
        }
        ```
        
5.  **Массовая запись в Redis:**
    
    -   Вызвать `redisCache.msetOrgDatasets(orgMap)` для массовой записи всех организаций в Redis.
        
6.  **Вернуть статистику:**
    
    -   Объект с метриками:
        
        ```javascript
        {
          processed: 100,    // Общее количество обработанных датасетов
          updated: 50,       // Количество обновленных организаций в Redis
          created: 10        // Количество новых организаций в Redis (опционально)
        }
        ```
        
7.  **Логирование:**
    
    -   Залогировать начало синхронизации: `logger.info('Cache warming started...')`.
        
    -   Залогировать завершение с статистикой: `logger.info('Cache warming completed', stats)`.

**Зависимости:**

-   `difyApi` (HTTP клиент Dify, должен быть реализован в `about/5.md`).
    
-   `redisCache` (репозиторий кэша, должен быть реализован в `about/4.md`).
    
-   Конфигурация (`config.dify.keys.admin`, `config.dify.api.pageSize`).
    
-   Логгер.

**Тестирование:**

-   **Unit-тест с моком Dify API:**
    
    -   Тест с одной страницей: мок возвращает 20 датасетов, метод получает все 20.
        
    -   Тест с несколькими страницами: мок возвращает по 50 датасетов на странице, метод получает все страницы (например, 3 страницы = 150 датасетов).
        
    -   Тест с пустым результатом: мок возвращает пустой массив, метод обрабатывает это корректно.
        
    -   Тест парсинга имен: массив датасетов с именами `KB_ADMIN_1`, `KB_HISTORY_1`, `KB_ADMIN_2`, метод корректно группирует по `orgId`.
        
    -   Тест с "чужими" датасетами: массив с датасетами, не соответствующими паттернам, метод игнорирует их.
        
-   **Интеграционный тест:**
    
    -   Вызвать `syncCacheWithDify` с реальным Dify (или качественным моком) и Redis.
        
    -   Проверить, что все датасеты синхронизированы с Redis.
        
    -   Проверить, что статистика возвращается корректно.

### 1.2 Интеграция в точку входа (`src/index.js`)

**Назначение:** Включить вызов `syncCacheWithDify` в последовательность запуска приложения.

**Алгоритм:**

1.  **Место в Startup Sequence:**
    
    -   После подключения к Redis и проверки конфига, но **ДО** запуска `initWorkers()`.
        
    -   Последовательность:
        
        ```javascript
        // 1. Инициализация конфигурации и логгера
        const config = require('./src/config');
        const logger = require('./src/utils/logger');
        
        // 2. Подключение к Redis
        const redisClient = require('./src/infrastructure/redis/client');
        await redisClient.connect();
        
        // 3. Проверка конфигурации
        // ...
        
        // 4. Cache Warming (НОВОЕ)
        try {
          logger.info('Cache warming started...');
          const stats = await OrganizationService.syncCacheWithDify();
          logger.info('Cache warming completed', stats);
        } catch (error) {
          logger.error('Cache warming failed:', error);
          process.exit(1); // Завершить процесс, так как работать с пустым кэшем бессмысленно
        }
        
        // 5. Запуск воркеров
        await initWorkers();
        ```
        
2.  **Обработка ошибок:**
    
    -   Если синхронизация упала с ошибкой -> завершить процесс (`process.exit(1)`), так как работать с пустым кэшем бессмысленно (чтение не будет работать).
        
    -   Логировать ошибку перед завершением процесса.

**Зависимости:**

-   `OrganizationService` (метод `syncCacheWithDify` должен быть реализован).
    
-   Redis клиент (должен быть подключен).
    
-   Конфигурация и логгер (должны быть инициализированы).

**Тестирование:**

-   **Интеграционный тест:**
    
    -   Запустить приложение и проверить, что `syncCacheWithDify` вызывается при старте.
        
    -   Проверить логи: должны быть сообщения "Cache warming started..." и "Cache warming completed".
        
    -   Проверить, что при ошибке синхронизации процесс завершается с кодом 1.
