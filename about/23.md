# Техническое задание: Финализация и Документация

**Контекст:** Весь функционал микросервиса реализован и протестирован. Теперь необходимо подготовить проект к эксплуатации: оптимизировать Docker-образ для продакшена (уменьшить размер, повысить безопасность) и написать исчерпывающую документацию для разработчиков и DevOps.

**Цель:** Реализовать Production-stage в Dockerfile и создать файл `README.md`, описывающий запуск, архитектуру и конфигурацию.

## 1\. Production Dockerfile

Доработать существующий `Dockerfile`, убедившись, что он соответствует Best Practices для Node.js в продакшене.

**Требования к стадии `production`:**

1.  **Base Image:** Использовать `node:lts-alpine` для минимизации размера.
    
2.  **System Dependencies:**
    
    -   **Важно:** Установить зависимости для сборки нативных модулей (если `bullmq` или другие пакеты этого потребуют): `apk add --no-cache python3 make g++`.
        
3.  **Environment:** Установить `NODE_ENV=production`.
    
4.  **Dependencies:**
    
    -   Копировать `package*.json`.
        
    -   Выполнять `npm ci --only=production --ignore-scripts`. Это исключит `devDependencies` (ESLint, Jest, Nodemon), что существенно уменьшит размер образа.
        
5.  **Security (Non-root user):**
    
    -   Не запускать приложение от `root`.
        
    -   Использовать встроенного пользователя `node` (есть в alpine образах).
        
    -   Выполнить `chown` для рабочей директории.
        
    -   Инструкция `USER node`.
        
6.  **Copy Source:** Копировать папку `src`.
    
7.  **Entrypoint:** Использовать `node src/index.js` (без npm wrapper, чтобы PID 1 корректно обрабатывал сигналы SIGTERM).

-   Название: Ticket AI Worker.
    
-   Краткое описание: "Асинхронный микросервис для обработки тикетов через Dify (External RAG, Classification)".
    

### 2.2 Архитектура (Ссылки)

-   Ссылка на `ai_microservice_spec.md` (наше основное ТЗ).
    
-   Краткая схема потоков: `Main App -> Redis (BullMQ) -> AI Worker <-> Dify API`.
    
-   Упоминание паттерна: **External RAG** (Воркер сам ищет контекст через Admin Key, затем вызывает Workflow).
    

### 2.3 Быстрый старт (Local Development)

1.  `cp .env.example .env` (и заполнить ключи).
    
2.  `docker-compose up -d`.
    
3.  `npm install`.
    
4.  `npm test`.

## 3\. CI/CD (Github Actions) - Опционально

Создать `.github/workflows/ci.yml`.

**Шаги:**

1.  Checkout code.
    
2.  Setup Node.js.
    
3.  Install dependencies (`npm ci`).
    
4.  Lint (`npm run lint`).
    
5.  Test (`npm test`).
    
    -   _Важно:_ Тесты должны использовать моки (`nock`), не требуя реального Dify.
