
# Техническое задание: Healthcheck Endpoint

**Контекст:** Микросервис работает как долгоживущий процесс без внешнего HTTP API для клиентов. Однако для корректной работы Docker Compose healthcheck и оркестраторов (Kubernetes, Docker Swarm) необходимо иметь HTTP-эндпоинт, который проверяет работоспособность всех компонентов сервиса. Простая проверка процесса Node.js не гарантирует, что воркеры живы и все зависимости (Redis, Dify) доступны.

**Цель:** Реализовать простой Express-сервер на отдельном порту с эндпоинтом `/health`, который выполняет проверку всех критических компонентов микросервиса и возвращает детальный статус каждого компонента.

## 1\. Установка зависимостей

-   `express`: Минимальный HTTP-сервер для healthcheck эндпоинта.

## 2\. Модуль Healthcheck (`src/infrastructure/healthcheck/server.js`)

Создать Express-сервер, который будет работать параллельно с основным приложением.

**Требования:**

1.  **Порт:**
    
    -   Использовать порт из конфига: `config.healthcheck.port` (по умолчанию `3000`).
        
    -   Порт должен быть настраиваемым через переменную окружения `HEALTHCHECK_PORT` в `.env` файле.
        
    -   **Важно:** Этот порт должен быть проброшен в Docker Compose и оркестраторах для healthcheck проверок.
        
2.  **Эндпоинт `GET /health`:**
    
    -   Выполнить проверку всех критических компонентов микросервиса.
        
    -   Вернуть детальный статус каждого компонента.
        
    -   **Формат ответа:**
        
        -   **Если все компоненты здоровы (HTTP 200):**
            
            JSON
            
                {
                  "status": "healthy",
                  "timestamp": "2024-01-15T10:30:00.000Z",
                  "checks": {
                    "redis": {
                      "status": "ok",
                      "message": "Connection successful"
                    },
                    "dify": {
                      "status": "ok",
                      "message": "API accessible"
                    },
                    "workers": {
                      "fastLane": {
                        "status": "ok",
                        "message": "Worker is running",
                        "activeJobs": 5
                      },
                      "slowLane": {
                        "status": "ok",
                        "message": "Worker is running",
                        "activeJobs": 2
                      }
                    }
                  }
                }
            
        -   **Если хотя бы один компонент нездоров (HTTP 503 Service Unavailable):**
            
            JSON
            
                {
                  "status": "unhealthy",
                  "timestamp": "2024-01-15T10:30:00.000Z",
                  "checks": {
                    "redis": {
                      "status": "ok",
                      "message": "Connection successful"
                    },
                    "dify": {
                      "status": "error",
                      "message": "Connection timeout",
                      "error": "ETIMEDOUT"
                    },
                    "workers": {
                      "fastLane": {
                        "status": "ok",
                        "message": "Worker is running"
                      },
                      "slowLane": {
                        "status": "error",
                        "message": "Worker is not running",
                        "error": "Worker connection lost"
                      }
                    }
                  }
                }
            
3.  **Проверки компонентов:**
    
    -   **Redis (кэш):**
        
        -   Выполнить `PING` через клиент Redis (`src/infrastructure/redis/client.js`).
            
        -   Проверить, что соединение активно и команда выполняется успешно.
            
        -   Таймаут: 2 секунды.
            
        -   Если проверка не прошла, вернуть статус `error` с описанием проблемы.
            
    -   **Dify API:**
        
        -   Выполнить простой запрос к Dify API (например, `GET /health` или `GET /info`, если такой эндпоинт существует, либо `GET /datasets?page=1&limit=1` с Admin Key).
            
        -   Проверить, что API доступен и отвечает (не 502, 503, таймаут).
            
        -   Таймаут: 5 секунд.
            
        -   Если проверка не прошла, вернуть статус `error` с описанием проблемы (например, "Connection timeout", "502 Bad Gateway").
            
    -   **Workers (BullMQ):**
        
        -   **Fast Lane Worker:**
            
            -   Проверить, что воркер запущен и соединение активно.
                
            -   Проверить статус воркера через `worker.isRunning()` (если такой метод доступен в BullMQ).
                
            -   Опционально: получить количество активных задач через `worker.getActiveJobs()` или аналогичный метод.
                
        -   **Slow Lane Worker:**
            
            -   Аналогично Fast Lane Worker.
                
        -   Если воркер не запущен или соединение потеряно, вернуть статус `error`.
            
4.  **Обработка ошибок:**
    
    -   Все проверки должны быть обернуты в `try/catch`.
        
    -   Если проверка компонента упала с исключением, вернуть статус `error` с описанием ошибки.
        
    -   Не допускать, чтобы ошибка в одной проверке приводила к падению всего healthcheck эндпоинта.
        
5.  **Таймауты:**
    
    -   Каждая проверка должна иметь свой таймаут, чтобы healthcheck не зависал надолго.
        
    -   Общий таймаут для всего healthcheck: 10 секунд (если проверки выполняются последовательно) или максимальный таймаут среди всех проверок (если параллельно).
        
6.  **Логирование:**
    
    -   Логировать результаты проверок на уровне `info` (успешные) и `warn` (неуспешные).
        
    -   Не логировать каждый запрос к `/health` (чтобы не засорять логи), но логировать изменения статуса компонентов.

## 3\. Интеграция в точку входа (`src/index.js`)

1.  Импортировать модуль healthcheck сервера.
    
2.  Запустить Express-сервер **после** инициализации всех компонентов (Redis, воркеры), но **до** завершения инициализации приложения.
    
3.  **Важно:** Healthcheck сервер должен запускаться асинхронно и не блокировать основной процесс.
    
4.  При Graceful Shutdown закрыть Express-сервер вместе с другими компонентами.

## 4\. Обновление конфигурации (`src/config`)

1.  Добавить в схему валидации (`src/config/schema.js`):
    
    -   `HEALTHCHECK_PORT`: Число, по умолчанию `3000`.
        
2.  Добавить в экспортируемый объект конфига (`src/config/index.js`):
    
    JavaScript
    
        healthcheck: {
          port: parseInt(process.env.HEALTHCHECK_PORT || '3000', 10),
        },
    

## 5\. Обновление Docker Compose (`docker-compose.yml`)

Добавить healthcheck для сервиса `worker`:

YAML

    healthcheck:
      test: ["CMD", "wget", "--quiet", "--tries=1", "--spider", "http://localhost:3000/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

**Примечание:** Использовать `wget` или `curl` для проверки. Если эти утилиты недоступны в образе `node:lts-alpine`, можно использовать `node` с простым HTTP-запросом или добавить утилиту в Dockerfile.

## 6\. Обновление `.env.example`

Добавить переменную:

```ini
# Healthcheck
HEALTHCHECK_PORT=3000
```

# Acceptance Criteria (Критерии приемки)

1.  \[ \] Установлен пакет `express`.
    
2.  \[ \] Express-сервер запускается на порту, указанном в конфиге (`HEALTHCHECK_PORT`, по умолчанию `3000`).
    
3.  \[ \] Эндпоинт `GET /health` возвращает HTTP 200 с детальным статусом всех компонентов, если все компоненты здоровы.
    
4.  \[ \] Эндпоинт `GET /health` возвращает HTTP 503 с детальным статусом всех компонентов, если хотя бы один компонент нездоров.
    
5.  \[ \] **Redis Check:** Проверка Redis выполняется через `PING` команду с таймаутом 2 секунды. Результат проверки включается в ответ healthcheck.
    
6.  \[ \] **Dify Check:** Проверка Dify API выполняется через простой запрос с таймаутом 5 секунд. Результат проверки включается в ответ healthcheck.
    
7.  \[ \] **Workers Check:** Проверка воркеров (Fast Lane и Slow Lane) выполняется через проверку статуса воркеров. Результат проверки включается в ответ healthcheck.
    
8.  \[ \] **Error Handling:** Если проверка одного компонента упала с ошибкой, остальные проверки продолжают выполняться, и ошибка включается в ответ healthcheck.
    
9.  \[ \] **Timeout Handling:** Все проверки имеют таймауты, и healthcheck не зависает при недоступности компонентов.
    
10. \[ \] **Configuration:** Порт healthcheck сервера настраивается через переменную окружения `HEALTHCHECK_PORT` в `.env` файле.
    
11. \[ \] **Docker Integration:** Docker Compose healthcheck настроен и корректно проверяет доступность эндпоинта `/health`.
    
12. \[ \] **Graceful Shutdown:** При завершении приложения Express-сервер корректно закрывается вместе с другими компонентами.
    
13. \[ \] **Logging:** Результаты проверок логируются (успешные на уровне `info`, неуспешные на уровне `warn`), но каждый запрос к `/health` не логируется, чтобы не засорять логи.
