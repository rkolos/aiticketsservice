# Техническое задание: Модуль Конфигурации и Логирования (Ticket AI Worker)

**Контекст:** Приложение нуждается в централизованном управлении настройками (Environment Variables) с жесткой валидацией при старте. Также необходима система структурированного логирования (JSON) для удобной отладки и мониторинга в Docker-среде.

**Цель:** Реализовать модули `src/config` (с валидацией через Joi) и `src/utils/logger` (на базе Winston), а также обновить точку входа для проверки их работы.

## 1\. Установка зависимостей

Необходимо установить следующие пакеты:

-   `dotenv` (для загрузки .env файлов).
    
-   `joi` (для валидации схемы конфигурации).
    
-   `winston` (для логирования).
    

## 2\. Модуль Конфигурации (`src/config`)

Создать папку `src/config` и реализовать логику загрузки и валидации.

### 2.1 Файл `src/config/schema.js` (Схема валидации)

Создать Joi-схему, описывающую все ожидаемые переменные окружения.

**Требования к полям:**

1.  **Server/App:**
    
    -   `NODE_ENV`: Строка, допустимые значения: `development`, `production`, `test`. По умолчанию `development`.
        
    -   `LOG_LEVEL`: Строка, допустимые значения: `error`, `warn`, `info`, `debug`. По умолчанию `info`.
        
    -   `HEALTHCHECK_PORT`: Число, по умолчанию `3000`. Порт для HTTP-сервера healthcheck эндпоинта.
        
2.  **Redis:**
    
    -   `REDIS_HOST`: Строка, обязательное.
        
    -   `REDIS_PORT`: Число, по умолчанию `6379`.
        
    -   `REDIS_PASSWORD`: Строка. Опционально (allow empty string), так как в dev-режиме пароля может не быть, но в продакшене он обязателен.
        
3.  **Dify API:**
    
    -   `DIFY_API_URL`: Строка (URL), обязательное.
        
    -   **`DIFY_KEY_ADMIN`**: Строка, обязательное. Это ключ с правами уровня Workspace или Dataset Operator, необходимый для создания баз знаний и выполнения поиска (Retrieval).
        
    -   `DIFY_KEY_CLASSIFIER`: Строка, обязательное (Workflow App Key).
        
    -   `DIFY_KEY_SUMMARIZER`: Строка, обязательное (Workflow App Key).
        
    -   `DIFY_KEY_RESPONSE_WORKFLOW`: Строка, обязательное (Workflow App Key).
        
4.  **Workers (BullMQ):**
    
    -   `WORKER_FAST_LANE_CONCURRENCY`: Число, по умолчанию `15` (консервативное значение между 10-20). Количество одновременных задач для Fast Lane воркера.
        
    -   `WORKER_SLOW_LANE_CONCURRENCY`: Число, по умолчанию `2`. Количество одновременных задач для Slow Lane воркера.
        
    -   **Важно:** Эти настройки позволяют тюнить производительность без пересборки контейнера. Значения должны быть настраиваемыми через `.env` файл, а не хардкодиться в `index.js`.
        

**Поведение:**

-   Схема должна разрешать неизвестные поля (`unknown: true`), чтобы не падать из-за системных переменных Docker.
    

### 2.2 Файл `src/config/index.js` (Точка входа конфига)

1.  Загрузить `.env` с помощью `dotenv`.
    
2.  Валидировать `process.env` через схему из п. 2.1.
    
3.  **Обработка ошибок:** Если валидация не прошла (например, нет ключа Dify), приложение должно **выбросить ошибку и завершиться** (Throw Error). Недопустимо запускать сервис с невалидным конфигом.
    
4.  **Экспорт:** Экспортировать объект конфигурации (не `process.env` напрямую!), сгруппированный логически:
    
    JavaScript
    
        module.exports = {
          env: process.env.NODE_ENV,
          logLevel: process.env.LOG_LEVEL,
          redis: {
            host: process.env.REDIS_HOST,
            port: parseInt(process.env.REDIS_PORT, 10),
            password: process.env.REDIS_PASSWORD, // Передаем пароль
          },
          dify: {
            url: process.env.DIFY_API_URL,
            keys: {
              admin: process.env.DIFY_KEY_ADMIN, // Ключ для dataset/retrieval операций
              classifier: process.env.DIFY_KEY_CLASSIFIER,
              summarizer: process.env.DIFY_KEY_SUMMARIZER,
              responseWorkflow: process.env.DIFY_KEY_RESPONSE_WORKFLOW,
            },
          },
          workers: {
            fastLane: {
              concurrency: parseInt(process.env.WORKER_FAST_LANE_CONCURRENCY || '15', 10),
            },
            slowLane: {
              concurrency: parseInt(process.env.WORKER_SLOW_LANE_CONCURRENCY || '2', 10),
            },
          },
          healthcheck: {
            port: parseInt(process.env.HEALTHCHECK_PORT || '3000', 10),
          },
        };
    

## 3\. Модуль Логирования (`src/utils/logger.js`)

Реализовать обертку над библиотекой `winston`.

**Требования:**

1.  **Формат вывода:**
    
    -   Если `NODE_ENV === 'development'`: Использовать `winston.format.simple()` или `colorize()` для читаемости в консоли разработчика.
        
    -   Если `NODE_ENV === 'production'`: Использовать `winston.format.json()` (структурированные логи для ELK/Graylog).
        
2.  **Уровень логирования:** Брать из конфига (`config.logLevel`).
    
3.  **Транспорт:** `Console` (вывод в STDOUT/STDERR). Файловый транспорт не нужен (в Docker логи пишутся в stdout).
    
4.  **Экспорт:** Экспортировать инстанс логгера.
    

## 4\. Точка входа (`src/index.js`)

Обновить файл `src/index.js`, чтобы проверить работу новых модулей.

1.  Импортировать конфиг.
    
2.  Импортировать логгер.
    
3.  Вывести приветственное сообщение: `logger.info('Ticket AI Worker started', { config: ... })`.
    
    -   _Примечание:_ При выводе конфига в лог **обязательно** маскировать секретные ключи (Dify Keys, Redis Password), чтобы они не утекли в логи.
        
4.  Добавить обработчик `process.on('uncaughtException')` и `unhandledRejection`, который логирует ошибку через `logger.error` и завершает процесс (exit 1).
    

# Acceptance Criteria (Критерии приемки)

1.  \[ \] Установлены `dotenv`, `joi`, `winston`.
    
2.  \[ \] При отсутствии обязательной переменной (например, `REDIS_HOST` или `DIFY_KEY_ADMIN`) в `.env`, команда `npm start` падает с понятной ошибкой валидации (Joi error).
    
3.  \[ \] При наличии всех переменных приложение запускается.
    
4.  \[ \] Объект `config` имеет правильную структуру с группировкой по сервисам (redis, dify) и содержит новые поля (`password`, `admin`).
    
5.  \[ \] Логгер корректно пишет в консоль (цветной текст в dev, JSON в prod).
    
6.  \[ \] В коде не осталось прямых обращений к `process.env` (кроме файла конфига).
    
7.  \[ \] В `.env.example` добавлены новые ключи (`REDIS_PASSWORD`, `DIFY_KEY_ADMIN`, `WORKER_FAST_LANE_CONCURRENCY`, `WORKER_SLOW_LANE_CONCURRENCY`).
    
8.  \[ \] **Concurrency Configuration:** Настройки concurrency для воркеров (`WORKER_FAST_LANE_CONCURRENCY`, `WORKER_SLOW_LANE_CONCURRENCY`) вынесены в `.env` файл, что позволяет тюнить производительность без пересборки контейнера.
    
9.  \[ \] **Healthcheck Configuration:** Порт healthcheck сервера настраивается через переменную окружения `HEALTHCHECK_PORT` в `.env` файле (по умолчанию `3000`).
