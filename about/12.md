# Техническое задание: Slow Lane Worker - Этап 1: File Service (Скачивание файлов)

**Контекст:** Загрузка файлов в `about/9.md` критична из-за потоков и таймаутов. На первом этапе реализуется изолированный сервис для скачивания файлов с поддержкой таймаутов, извлечения размера файла и корректного закрытия стримов.

**Цель:** Реализовать сервис `FileService.downloadStream` изолированно, который будет использоваться для скачивания файлов перед загрузкой в Dify. Сервис должен корректно обрабатывать таймауты, извлекать размер файла и закрывать стримы при ошибках.

## 1. Задачи реализации

### 1.1 Реализовать `src/services/FileService.js`

**Назначение:** Простая обертка для скачивания файлов, чтобы не дублировать код axios в воркере.

**Метод:**

```javascript
async downloadStream(url) {
  // Реализация
}
```

**Алгоритм:**

1.  **Создать Axios запрос с настройками:**
    
    -   `method: 'GET'`
        
    -   `url`: URL файла для скачивания
        
    -   `responseType: 'stream'` — получение данных в виде потока
        
    -   **Таймаут на подключение (`timeout`):**
        
        -   Установить таймаут на установление соединения и получение ответа (например, 30 секунд).
            
        -   Значение должно быть настраиваемым через конфиг: `config.fileService.connectionTimeout` (по умолчанию 30000 мс).
            
        -   Если соединение не установилось в течение этого времени, axios выбросит ошибку `ETIMEDOUT`.
            
2.  **Извлечь заголовок `content-length`:**
    
    -   После получения ответа проверить заголовок `content-length` в `response.headers['content-length']`.
        
    -   Преобразовать значение в число (байты).
        
    -   Если заголовок отсутствует, вернуть `null` (не критично, но желательно для корректной загрузки в Dify).
        
3.  **Настроить idle timeout для стрима:**
    
    -   **Проблема:** Если соединение с S3 (или другим источником файлов) зависнет (нет данных, но соединение открыто), воркер может висеть вечно, занимая слот `concurrency` и блокируя обработку других задач.
        
    -   **Решение:** Установить таймаут на отсутствие данных в стриме (idle timeout). Если в течение определенного времени (например, 60 секунд) не приходят новые данные, стрим должен быть прерван с ошибкой.
        
    -   **Реализация:** Использовать таймер на события стрима:
        
        ```javascript
        const stream = response.data;
        let lastDataTime = Date.now();
        const IDLE_TIMEOUT = config.fileService.idleTimeout || 60000; // 60 секунд
        
        let idleTimer = null;
        
        stream.on('data', (chunk) => {
          // Сбросить таймер при получении данных
          lastDataTime = Date.now();
          if (idleTimer) clearTimeout(idleTimer);
          
          idleTimer = setTimeout(() => {
            if (Date.now() - lastDataTime > IDLE_TIMEOUT) {
              stream.destroy(new Error('Stream idle timeout: no data received for 60 seconds'));
              clearTimeout(idleTimer);
            }
          }, 1000); // Проверка каждую секунду
        });
        
        stream.on('end', () => {
          if (idleTimer) clearTimeout(idleTimer);
        });
        
        stream.on('error', () => {
          if (idleTimer) clearTimeout(idleTimer);
        });
        ```
        
    -   **Важно:** Таймаут должен быть настраиваемым через конфиг (например, `config.fileService.idleTimeout`), чтобы можно было изменять его в зависимости от размера файлов и скорости сети.
        
4.  **Обработать ошибки:**
    
    -   **404 Not Found:** Выбросить ошибку с кодом `FILE_NOT_FOUND`.
        
    -   **Таймаут подключения (`ETIMEDOUT`):** Выбросить ошибку с кодом `CONNECTION_TIMEOUT`.
        
    -   **Idle timeout:** Выбросить ошибку с кодом `IDLE_TIMEOUT`.
        
    -   **Другие ошибки:** Выбросить общую ошибку с кодом `DOWNLOAD_ERROR`.
        
5.  **Корректное закрытие стрима при ошибках:**
    
    -   При любой ошибке вызвать `stream.destroy()` для закрытия стрима.
        
    -   Обработать ошибки закрытия стрима (не выбрасывать повторно, если стрим уже закрыт).
        
    -   Очистить таймеры при ошибках.

**Возвращаемое значение:**

```javascript
{
  stream: ReadStream,    // Поток данных файла с настроенными таймаутами
  size: number | null    // Размер файла в байтах (из заголовка content-length)
}
```

**Зависимости:**

-   `axios` (HTTP клиент).
    
-   Логгер.
    
-   Конфигурация (для таймаутов: `config.fileService.connectionTimeout`, `config.fileService.idleTimeout`).

## 2. Структура файла

**Файл:** `src/services/FileService.js`

**Импорты:**

```javascript
const axios = require('axios');
const logger = require('../utils/logger');
const config = require('../config');
```

**Классы ошибок:**

```javascript
class FileServiceError extends Error {
  constructor(message, code) {
    super(message);
    this.code = code;
  }
}

class FileNotFoundError extends FileServiceError {
  constructor(url) {
    super(`File not found: ${url}`, 'FILE_NOT_FOUND');
    this.url = url;
  }
}

class ConnectionTimeoutError extends FileServiceError {
  constructor(url) {
    super(`Connection timeout: ${url}`, 'CONNECTION_TIMEOUT');
    this.url = url;
  }
}

class IdleTimeoutError extends FileServiceError {
  constructor(url) {
    super(`Stream idle timeout: no data received for 60 seconds: ${url}`, 'IDLE_TIMEOUT');
    this.url = url;
  }
}
```

**Экспорт:**

-   Класс `FileService` с методом `downloadStream`.
    
-   Классы ошибок (для использования в других модулях).

## 3. Тестирование

### 3.1 Unit-тест с моком axios

**Цель:** Проверить извлечение `content-length` и обработку различных сценариев.

**Тесты:**

-   **Успешное скачивание с content-length:**
    
    -   Мок возвращает ответ с заголовком `content-length: 1024`.
        
    -   Проверить, что метод возвращает `{ stream, size: 1024 }`.
        
-   **Скачивание без content-length:**
    
    -   Мок возвращает ответ без заголовка `content-length`.
        
    -   Проверить, что метод возвращает `{ stream, size: null }`.
        
-   **Ошибка 404:**
    
    -   Мок возвращает ошибку 404.
        
    -   Проверить, что метод выбрасывает ошибку `FileNotFoundError`.
        
    -   Проверить, что стрим закрыт (`stream.destroy()` вызван).

### 3.2 Unit-тест idle timeout

**Цель:** Проверить, что idle timeout корректно закрывает зависший стрим.

**Тест:**

-   Симулировать зависший стрим (мок не отправляет данные в течение 60+ секунд).
    
-   Проверить, что через 60 секунд стрим закрыт и выброшена ошибка `IdleTimeoutError`.
    
-   Проверить, что таймер сброшен при получении данных.

### 3.3 Интеграционный тест

**Цель:** Проверить скачивание реального файла из тестового URL.

**Тест:**

-   Скачать реальный файл из тестового URL (например, небольшой PDF или изображение).
    
-   Проверить, что метод возвращает стрим и размер файла.
    
-   Проверить, что стрим можно прочитать и получить данные файла.
