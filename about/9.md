# Техническое задание: Organization Service - Этап 1: Core Cache Operations

**Контекст:** Модуль `OrganizationService` в `about/7.md` отвечает за синхронизацию, ленивую загрузку и инвалидацию кэша. На первом этапе реализуются базовые операции чтения и очистки кэша, которые позволяют другим частям системы работать в режиме "чтения".

**Цель:** Реализовать методы `getKbIdsOrThrow` (чтение из Redis) и `invalidateOrgCache` (очистка кэша), которые являются основой для всех остальных операций.

## 1. Задачи реализации

### 1.1 Реализовать `getKbIdsOrThrow(orgId)` (Strict Read)

**Назначение:** Получить ID баз знаний для организации из Redis с выбросом ошибки, если данных нет. Метод используется для операций чтения (RAG / Retrieval).

**Метод:**

```javascript
async getKbIdsOrThrow(orgId) {
  // Реализация
}
```

**Алгоритм:**

1.  **Запросить Redis:**
    
    -   Вызвать `redisCache.getOrgDatasets(orgId)` для получения данных из кэша.
        
2.  **Проверка наличия данных:**
    
    -   Если данных нет (`null` или `undefined`) -> Выбросить ошибку `KbNotFoundError`.
        
    -   Если поле `adminKbId` или `historyKbId` пустое -> Выбросить ошибку `KbNotFoundError`.
        
3.  **Возврат результата:**
    
    -   Если данные найдены, вернуть объект:
        
        ```javascript
        {
          adminKbId: 'ds-123',      // ID базы знаний для файлов
          historyKbId: 'ds-456'     // ID базы знаний для истории тикетов
        }
        ```
        
4.  **Важно:** Не делать запросов к Dify. Строгая проверка по кэшу. Если базы нет в кэше, значит она еще не создана (нет файлов), и искать там нечего.

**Зависимости:**

-   `redisCache` (репозиторий кэша, должен быть реализован в `about/4.md`).
    
-   `KbNotFoundError` (кастомная ошибка из `src/core/errors.js`).
    
-   Логгер (для логирования операций, опционально).

**Тестирование:**

-   **Unit-тест с моком Redis:**
    
    -   Тест успешного чтения: мок возвращает данные, метод возвращает объект с `adminKbId` и `historyKbId`.
        
    -   Тест отсутствия данных: мок возвращает `null`, метод выбрасывает `KbNotFoundError`.
        
    -   Тест частичных данных: мок возвращает объект только с `adminKbId`, метод выбрасывает `KbNotFoundError` (если `historyKbId` обязателен) или возвращает объект с `historyKbId: null` (в зависимости от требований).

### 1.2 Реализовать `invalidateOrgCache(orgId)` (Stale Cache Strategy)

**Назначение:** Инвалидация кэша организации при обнаружении несоответствия между Redis и Dify. Используется при получении специфических ошибок от Dify API, указывающих на отсутствие датасета.

**Метод:**

```javascript
async invalidateOrgCache(orgId) {
  // Реализация
}
```

**Алгоритм:**

1.  **Удалить ключ организации из Redis:**
    
    -   Вызвать `redisCache.deleteOrgDatasets(orgId)` для удаления ключа из Redis.
        
2.  **Логировать событие:**
    
    -   Уровень логирования: `warn`.
        
    -   Сообщение: `Cache invalidated for org ${orgId}`.
        
    -   Дополнительные данные: `{ orgId, reason: 'stale_cache' }` (или другая причина, если передается).
        
3.  **Возврат результата:**
    
    -   Вернуть результат удаления (true/false или количество удаленных ключей, в зависимости от реализации `deleteOrgDatasets`).
        
4.  **Важно:** После инвалидации следующий запрос через `ensureAdminKb` или `ensureHistoryKb` спровоцирует создание новой базы или актуализацию данных из Dify.

**Зависимости:**

-   `redisCache` (репозиторий кэша).
    
-   Логгер (для логирования события инвалидации).

**Тестирование:**

-   **Unit-тест с моком Redis:**
    
    -   Тест успешного удаления: мок подтверждает удаление, метод возвращает успешный результат.
        
    -   Тест отсутствия ключа: мок возвращает `false` или `0`, метод обрабатывает это корректно (не выбрасывает ошибку).
        
    -   Проверить, что событие инвалидации залогировано с уровнем `warn`.

**Класс ошибки (если не создан в `src/core/errors.js`):**

```javascript
class KbNotFoundError extends Error {
  constructor(orgId) {
    super(`Knowledge base not found for organization: ${orgId}`);
    this.orgId = orgId;
    this.code = 'KB_NOT_FOUND';
  }
}
```

**Экспорт:**

-   Класс `OrganizationService` с методами `getKbIdsOrThrow` и `invalidateOrgCache`.
    
-   Класс ошибки `KbNotFoundError` (для использования в других модулях).

## 3. Критерий завершения этапа

Базовые методы работают и покрыты тестами. Можно использовать для чтения ID баз в других модулях (например, в Fast Lane Worker) и для инвалидации кэша при ошибках. Это позволяет другим частям системы работать в режиме "чтения".

## 4. Зависимости от других этапов

-   **Redis Cache (`about/4.md`):** Репозиторий кэша должен быть реализован с методами `getOrgDatasets` и `deleteOrgDatasets`.
    
-   **Логгер (`about/3.md`):** Логгер должен быть доступен.
    
-   **Кастомные ошибки (`src/core/errors.js`):** Класс `KbNotFoundError` должен быть определен.

## 5. Интеграция с другими модулями

-   **Fast Lane Worker (`about/8.md`):** Метод `getKbIdsOrThrow` будет использоваться для получения ID баз знаний перед поиском чанков.
    
-   **Error Handler (`about/10.md`):** Метод `invalidateOrgCache` будет вызываться при ошибках отсутствия ресурсов.
