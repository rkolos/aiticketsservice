# Техническое задание: Поддержка параметра `lang` (Мультиязычность)

**Контекст:** В текущей реализации ответы LLM и суммаризация тикетов генерируются на языке, заданном в системном промпте. Для поддержки мультиязычных пользователей необходимо динамически управлять языком генерации через параметры задачи.

**Цель:** Добавить поддержку необязательного параметра `lang` (язык ответа) в пейлоады задач очередей и передавать его в Dify Workflows "как есть". Это позволит формировать ответы, краткие описания и архивы тикетов на языке, запрошенном клиентом. Системные промпты в Dify будут переведены на английский язык.

## 1\. Обновление контрактов данных (Job Payloads)

Необходимо обновить ожидаемую структуру входных данных для задач в `src/core/types.js` (или в документации к джобам).

**Новый параметр:**

-   **`lang`** (string, optional): Код языка (например, `'ru'`, `'en'`, `'es'`, `'de'`).
    
-   **Значение по умолчанию:** Отсутствует. Если параметр не передан, он не отправляется в Dify (или отправляется как `null`/`undefined`), оставляя выбор языка на усмотрение логики самого Workflow.
    

### 1.1 Задача `CMD_GEN_RESPONSE` (Fast Lane)

Используется для генерации ответа пользователю.

JSON

    {
      "action": "CMD_GEN_RESPONSE",
      "orgId": "123",
      "query": "How to reset password?",
      "history": [...],
      "lang": "en",  // <--- Новый необязательный параметр
      "meta": { ... }
    }

### 1.2 Задача `CMD_ARCHIVE_TICKET` (Slow Lane)

Используется для создания краткого описания и архивации решенного тикета.

JSON

    {
      "action": "CMD_ARCHIVE_TICKET",
      "orgId": "123",
      "fullTicketHistory": [...],
      "lang": "es",  // <--- Новый необязательный параметр
      "meta": { ... }
    }

## 2\. Доработка Воркеров

Необходимо обновить логику подготовки переменных (`inputs`) перед вызовом `difyApi.runWorkflow`. Воркер должен просто пробрасывать значение `lang`, если оно есть.

### 2.1 Fast Lane Worker (`src/workers/fastLaneProcessor.js`)

В обработчике `CMD_GEN_RESPONSE` (Этап 4, см. `about/18.md`):

1.  Извлечь `lang` из `job.data`.
    
2.  Добавить переменную `language` в `inputs` при вызове Dify.
    

JavaScript

    const inputs = {
      query: query,
      history: formattedHistory,
      context: context,
      language: job.data.lang // Передаем значение (или undefined)
    };
    
    await difyApi.runWorkflow(key, inputs, user);

### 2.2 Slow Lane Worker (`src/workers/slowLaneProcessor.js`)

В обработчике `CMD_ARCHIVE_TICKET` (см. `about/15.md`):

1.  Извлечь `lang` из `job.data`.
    
2.  Добавить переменную `language` в `inputs` при вызове Dify.
    

JavaScript

    const inputs = {
      ticket_history: formattedHistory,
      language: job.data.lang // Передаем значение (или undefined)
    };
    
    await difyApi.runWorkflow(summarizerKey, inputs, uniqueId);

## 4\. Acceptance Criteria (Критерии приемки)

1.  \[ \] **Передача параметра:** Воркеры (`fastLaneProcessor`, `slowLaneProcessor`) извлекают `lang` из задачи и передают его как `language` в `difyApi.runWorkflow` без изменений.
    
2.  \[ \] **Отсутствие хардкода:** В коде воркеров нет значений по умолчанию (например, `'ru'`).
    
3.  \[ \] **Support Helper:** При передаче `lang='en'` в `CMD_GEN_RESPONSE`, сгенерированный ответ приходит на английском языке.
    
4.  \[ \] **Summarizer:** При передаче `lang='es'` в `CMD_ARCHIVE_TICKET`, итоговая суммаризация формируется на испанском языке.
    
5.  \[ \] **Гибкость:** Если `lang` не передан, Dify корректно отрабатывает сценарий (например, отвечает на языке запроса или использует дефолтное поведение, заложенное в промпте).
