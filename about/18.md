# Техническое задание: Fast Lane Worker - Этап 4: Генерация (Final Generation)

**Контекст:** Задача `CMD_GEN_RESPONSE` в `about/8.md` включает в себя поиск, подсчет токенов, обрезку контекста и генерацию. На четвертом этапе подключается генерация ответа через Dify Workflow и извлечение usage для биллинга.

**Цель:** Реализовать полный цикл External RAG: поиск -> сборка контекста -> обрезка -> генерация -> извлечение usage -> возврат результата.

## 1. Задачи реализации

### 1.1 Интеграция с Dify Workflow

**Назначение:** Вызвать Dify Workflow для генерации ответа на основе собранного контекста.

**Задачи:**

1.  **Вызвать `difyApi.runWorkflow`:**
    
    -   Использовать ключ `config.dify.keys.responseWorkflow` для авторизации.
        
    -   Передать переменные в формате, требуемом Dify Workflow:
        
        ```javascript
        {
          query: "...",           // Исходный запрос пользователя
          history: "...",         // Отформатированная история (из этапа 3)
          context: "..."         // Обрезанный контекст из чанков (из этапа 3)
        }
        ```
        
2.  **Обработать ответ Workflow:**
    
    -   Извлечь текст ответа из `outputs.text` (или другого поля, в зависимости от структуры Workflow).
        
    -   Извлечь источники (sources) из ответа, если они доступны.
        
    -   Обработать ошибки Workflow (например, таймауты, ошибки генерации).

**Зависимости:**

-   `difyApi.runWorkflow` (метод должен быть реализован в `about/5.md`).
    
-   Конфигурация (`config.dify.keys.responseWorkflow`).
    
-   Отформатированные переменные из этапа 3 (`14_3.md`).

### 1.2 Интеграция BillingService

**Назначение:** Извлечь usage (количество токенов) из ответа Dify для биллинга.

**Задачи:**

1.  **Использовать `BillingService.extractUsage`:**
    
    -   Вызвать `BillingService.extractUsage(response)` для извлечения токенов из ответа Dify.
        
    -   Метод должен извлекать:
        
        -   `promptTokens` — токены во входном промпте.
            
        -   `completionTokens` — токены в сгенерированном ответе.
            
        -   `totalTokens` — общее количество токенов.
            
2.  **Добавить usage в результат:**
    
    -   Включить объект `usage` в результат, отправляемый в `resultQueue`:
        
        ```javascript
        {
          success: true,
          data: {
            text: "...",
            sources: [...],
            usage: {
              promptTokens: 1000,
              completionTokens: 500,
              totalTokens: 1500
            }
          }
        }
        ```

**Зависимости:**

-   `BillingService` (должен быть реализован в `about/10.md`).

### 1.3 Обработка ошибок

**Назначение:** Обработать ошибки генерации и применить стратегию инвалидации кэша при необходимости.

**Задачи:**

1.  **Использовать `ErrorHandler` для нормализации ошибок:**
    
    -   Вызвать `ErrorHandler.normalizeError(error)` для стандартизации формата ошибки.
        
    -   Создать error payload через `ErrorHandler.createErrorPayload(error, jobId, orgId)`.
        
2.  **Применить стратегию инвалидации кэша:**
    
    -   Вызвать `ErrorHandler.handleDifyResourceError(error, orgId)` перед созданием error payload.
        
    -   Метод автоматически проверит, является ли ошибка ошибкой отсутствия ресурса (например, `dataset_not_found`, 404 статус).
        
    -   Если ошибка связана с отсутствием ресурса, метод вызовет `OrganizationService.invalidateOrgCache(orgId)` для инвалидации кэша.
        
3.  **Отправить ошибку в resultQueue:**
    
    -   Отправить error payload в `resultQueue` с корректным форматом.
        
    -   Выбросить ошибку (`throw err`), чтобы BullMQ пометил джоб как Failed и применил стратегию Retry (если это временная ошибка).

**Зависимости:**

-   `ErrorHandler` (должен быть реализован в `about/10.md`).
    
-   `OrganizationService` (для инвалидации кэша).

### 1.4 Финальная интеграция

**Назначение:** Объединить все этапы в единый поток обработки.

**Задачи:**

1.  **Объединить все этапы:**
    
    -   Шаг 1: Identify Datasets (из этапа 2).
        
    -   Шаг 2: Retrieval (из этапа 2).
        
    -   Шаг 3: Context Assembly (из этапа 3).
        
    -   Шаг 4: Context Pruning (из этапа 3).
        
    -   Шаг 5: Generation (из этапа 4).
        
    -   Шаг 6: Extract Usage (из этапа 4).
        
    -   Шаг 7: Return Result (из этапа 4).
        
2.  **Структурировать финальный результат:**
    
    -   Формат результата:
        
        ```javascript
        {
          success: true,
          data: {
            text: "...",              // Текст ответа из Workflow
            sources: [...],           // Источники (чанки, использованные для ответа)
            usage: {
              promptTokens: 1000,
              completionTokens: 500,
              totalTokens: 1500
            }
          }
        }
        ```
        
3.  **Отправить результат в resultQueue:**
    
    -   Отправить результат в `resultQueue` с корректным `jobId` и форматом.

**Зависимости:**

-   Все предыдущие этапы (2, 3, 4).
    
-   `resultQueue` (очередь результатов).
