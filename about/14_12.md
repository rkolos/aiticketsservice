# Техническое задание: Roadmap реализации (Оптимальная последовательность)

**Контекст:** Проект хорошо проработан архитектурно, но некоторые этапы слишком объемны для реализации "в один присест". Для эффективной разработки необходимо определить оптимальную последовательность реализации модулей с учетом зависимостей.

**Цель:** Предоставить детальный roadmap имплементации, который позволит реализовывать функциональность поэтапно с возможностью тестирования на каждом этапе и минимизацией зависимостей.

## 7. Рекомендации по тестированию

1.  **Unit-тесты для утилит:**
    
    -   Тестировать утилиты изолированно с моками.
        
    -   Покрыть edge cases (null, undefined, пустые данные, очень длинные данные).
        
2.  **Интеграционные тесты для сервисов:**
    
    -   Тестировать сервисы с реальными зависимостями (Redis, Dify) или с качественными моками.
        
    -   Проверять реальные сценарии использования.
        
3.  **E2E тесты для воркеров:**
    
    -   Тестировать полный цикл обработки задачи от получения из очереди до отправки результата.
        
    -   Использовать тестовые очереди и тестовые данные.

## 8. Критерии готовности к следующему этапу

Перед переходом к следующему этапу необходимо:

1.  Все задачи текущего этапа реализованы.
    
2.  Код покрыт тестами (Unit или интеграционными, в зависимости от этапа).
    
3.  Тесты проходят успешно.
    
4.  Код проходит линтер и форматтер.
    
5.  Документация обновлена (если требуется).
