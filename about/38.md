### Параллельное выполнение задач (2-этапная схема)

**Цель:** Сократить время ответа (`handleGenResponse`) за счет параллельного выполнения независимых I/O операций.

**Область изменений:** `src/workers/fastLaneWorker.js`, функция `handleGenResponse`.

**Описание задачи:** Разбить линейную цепочку выполнения на два этапа параллелизма.

**Техническая реализация:**

1.  **Этап 1 (Подготовка):**
    
    -   Заменить последовательные `await` на `Promise.all`:
        
        JavaScript
        
            const [simplificationResult, adminKbId, historyKbId] = await Promise.all([
               difyApi.simplifyUserQuery(query, orgId),
               OrganizationService.ensureAdminKb(orgId),
               OrganizationService.ensureHistoryKb(orgId)
            ]);
        
    -   Извлечь `processedQuery` из результата.
        
2.  **Этап 2 (Поиск):**
    
    -   Сформировать массив промисов поиска.
        
    -   Заменить последовательные поиски на `Promise.allSettled` (чтобы ошибка в одном поиске не валила второй, либо `Promise.all`, если ошибка критична — _рекомендуется_ `allSettled` для надежности поиска):
        
        JavaScript
        
            const [adminResult, historyResult] = await Promise.allSettled([
               adminKbId ? difyApi.retrieve(adminKbId, processedQuery) : Promise.resolve([]),
               historyKbId ? difyApi.retrieveChunks(..., historyKbId, processedQuery) : Promise.resolve([])
            ]);
        
    -   Обработать результаты, собрав успешные ответы в общий массив `retrievedRecords`.
        

**Критерии приёмки (Acceptance Criteria):**

-   \[ \] Время выполнения функции (метрика `processingTimeMs`) уменьшилось на величину, примерно равную времени выполнения `simplifyUserQuery` + `retrieveChunks`.
    
-   \[ \] Результат `simplifyUserQuery` используется для поиска в **обеих** базах знаний.
    
-   \[ \] Если одна из баз знаний недоступна (ошибка поиска), поиск во второй все равно выполняется и возвращает результат.
