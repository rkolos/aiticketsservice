### ТЗ №1. Оптимизация алгоритма обрезки контекста (`pruneContext`)

**Цель:** Устранить квадратичную сложность алгоритма обрезки контекста, снизив нагрузку на CPU при обработке больших объемов текста.

**Область изменений:** `src/workers/fastLaneWorker.js`

**Описание задачи:** Переписать функцию `pruneContext`. Текущая реализация в цикле удаляет чанк, заново собирает строку и заново токенизирует её. Новая реализация должна токенизировать чанки один раз перед циклом.

**Техническая реализация:**

1.  Принимать на вход массив чанков (`adminChunks`, `historyChunks`).
    
2.  **Один раз** пройтись по массивам и вычислить количество токенов для каждого чанка (сохранить в структуру вида `{ ...chunk, tokens: N }`).
    
3.  Вычислить суммарное количество токенов `currentTotal`.
    
4.  В цикле `while (currentTotal > limit)`:
    
    -   Удалять чанк из массива (согласно приоритету: сначала history с конца, потом admin с конца).
        
    -   Вычитать количество токенов удаленного чанка из `currentTotal` (математическая операция, а не пересчет).
        
    -   Для последнего чанка, если требуется частичная обрезка, использовать `slice` строки и пересчитать токены только для этого одного чанка.
        
5.  Вызвать `assembleContext` **только один раз** в самом конце, когда итоговый набор чанков сформирован.
    

**Критерии приёмки (Acceptance Criteria):**

-   \[ \] Функция `tokenCounter.countTokens` вызывается `N` раз (где N — кол-во чанков) + 1 раз (финальная проверка, опционально), а не `N * M` раз.
    
-   \[ \] Логика приоритетов сохранена: сначала удаляется история, потом админ-чанки.
    
-   \[ \] Итоговый контекст гарантированно меньше или равен `contextLimit`.
    
-   \[ \] Отсутствует конкатенация строк внутри цикла `while`.
