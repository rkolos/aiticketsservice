# Техническое задание: Настройка Docker окружения (Ticket AI Worker)

**Контекст:** Микросервис `ticket-ai-worker` должен работать в контейнеризированной среде. Для локальной разработки необходимо оркестрировать запуск самого приложения (в режиме разработки с Hot Reload) и Redis (как основного брокера очередей и кэша).

**Цель:** Создать `Dockerfile` и `docker-compose.yml`, обеспечивающие быстрый старт разработки и готовность к будущему продакшн-деплою.

## 1\. Файл `.dockerignore`

Создать файл `.dockerignore` в корне проекта, чтобы исключить лишние файлы из контекста сборки:

-   `node_modules`
    
-   `.git`
    
-   `docker` (папка с данными, если она монтируется локально)
    
-   `coverage`
    
-   `tests`
    
-   `*.log`
    
-   `.env` (секреты не должны попадать в образ)
    
-   `.DS_Store`
    

## 2\. Dockerfile (Multi-stage)

Необходимо создать `Dockerfile` в корне проекта (или в папке `docker/`, но тогда учесть контекст). Рекомендуется держать в корне для простоты.

**Требования к стадиям сборки:**

1.  **Base Stage:**
    
    -   Образ: `node:lts-alpine` (или конкретная версия, например, 20-alpine).
        
    -   Рабочая директория: `/app`.
        
    -   Копирование `package.json` и `package-lock.json`.
        
    -   Установка зависимостей (`npm ci` для чистоты).
        
2.  **Development Stage (Target):**
    
    -   Базируется на Base Stage.
        
    -   Устанавливает `nodemon` глобально или использует из `devDependencies`.
        
    -   Команда запуска: `npm run dev` (должен запускать nodemon).
        
3.  **Production Stage (Target) - задел на будущее:**
    
    -   Базируется на Base Stage.
        
    -   Установка только production зависимостей (`npm ci --only=production`).
        
    -   Копирование исходного кода `src`.
        
    -   Пользователь: переключиться на `node` (non-root user) для безопасности.
        
    -   Команда запуска: `node src/index.js`.
        

## 3\. Docker Compose (Локальная разработка)

Создать `docker-compose.yml` в корне проекта.

**Сервис 1: `redis`**

-   **Образ:** `redis:alpine`.
    
-   **Имя контейнера:** `ticket-ai-redis`.
    
-   **Порты:** Пробросить стандартный порт `6379:6379` (для возможности подключения локальных GUI клиентов).
    
-   **Volumes:**
    
    -   Монтировать том для персистентности данных: `./docker/redis_data:/data`.
        
    -   Обязательно добавить этот путь в `.gitignore`.
        
-   **Healthcheck:** Проверка доступности Redis (`redis-cli ping`).
    

**Сервис 2: `worker` (Наше приложение)**

-   **Сборка (Build):**
    
    -   Контекст: текущая директория (`.`).
        
    -   Dockerfile: `Dockerfile`.
        
    -   Target: `development` (или имя стадии для разработки).
        
-   **Имя контейнера:** `ticket-ai-worker`.
    
-   **Volumes (Hot Reload):**
    
    -   Монтировать локальную папку `src` в `/app/src`: `- ./src:/app/src`.
        
    -   Важно: Использовать технику "Anonymous Volume" для `node_modules`, чтобы локальная папка не затирала модули внутри контейнера (`- /app/node_modules`).
        
-   **Env File:** Подключить файл `.env`.
    
-   **Depends On:** Зависеть от сервиса `redis` (condition: service\_healthy).
    
-   **Среда (Environment):**
    
    -   Переопределить `REDIS_HOST` на имя сервиса Redis (`redis`).
        
-   **Healthcheck:**
    
    -   Настроить healthcheck для проверки работоспособности сервиса через HTTP-эндпоинт `/health`.
        
    -   **Test:** `wget --quiet --tries=1 --spider http://localhost:3000/health` (или `curl -f http://localhost:3000/health || exit 1`).
        
    -   **Interval:** `30s` (проверка каждые 30 секунд).
        
    -   **Timeout:** `10s` (максимальное время ожидания ответа).
        
    -   **Retries:** `3` (количество попыток перед пометкой как unhealthy).
        
    -   **Start Period:** `40s` (время на инициализацию перед началом проверок).
        
    -   **Примечание:** Если `wget` или `curl` недоступны в образе `node:lts-alpine`, можно использовать `node` с простым HTTP-запросом или добавить утилиту в Dockerfile.
        

## 4\. Скрипты NPM

Добавить (или проверить) в `package.json` скрипты для управления Docker (опционально, для удобства):

-   `"docker:up"`: "docker-compose up -d"
    
-   `"docker:down"`: "docker-compose down"
    
-   `"docker:build"`: "docker-compose build"
    

# Acceptance Criteria (Критерии приемки)

1.  \[ \] Файл `.dockerignore` существует и содержит `node_modules` и `.env`.
    
2.  \[ \] `Dockerfile` реализует как минимум стадию для разработки.
    
3.  \[ \] `docker-compose.yml` корректен и валиден.
    
4.  \[ \] Команда `docker-compose up` успешно поднимает оба контейнера (`worker` и `redis`).
    
5.  \[ \] В логах контейнера `worker` видно сообщение о запуске (из `index.js`).
    
6.  \[ \] Изменения в файле `src/index.js` на хост-машине приводят к автоматическому перезапуску приложения внутри контейнера (работает Hot Reload).
    
7.  \[ \] Данные Redis сохраняются после перезапуска контейнера (проверяется наличием файлов в `./docker/redis_data`).
    
8.  \[ \] **Healthcheck:** Docker Compose healthcheck настроен для сервиса `worker` и корректно проверяет доступность эндпоинта `/health` на порту 3000.
